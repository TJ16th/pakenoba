# 新パケノバ コマンド、MCP、エージェントの欄、履歴の検討

- 作成日: 2026-11-24
- 状態: 5 章の 1（コマンドの入口と操作の記録）、2 の画面なしの MCP、3 のエージェントの欄、4 の版を残す、を作った（2026-11-24）
- 関連: [画面設計の検討](ui-design.md)、[案件の保存の検討](project-file.md)、[レイヤーの検討](layers.md)

本人からの要望（2026-11-24）は 3 つ。

- MCP にしっかり対応する（ほかの AI のアプリから、パケノバを動かせる）。
- 最近のソフトのように、画面の右の端でエージェントと対話しながら直せるようにする。つなぎ先は GitHub Copilot、OpenAI の API、Anthropic の API など。
- 制作の履歴（この絵を足した、それをこう直した）を残すかを考える。Git を中に入れるかも含めて。ただし、絵のデータを細かく残し続けて大きくなりすぎるのは避けたい。

## 1. 考え方: すべての操作を「コマンド」にする

PhotoCraft と VectorCraft は、すべての操作を約 700 個の名前つきのコマンドとして登録し、画面、コマンドライン、外からの操作（制御チャネル）、MCP が、同じコマンドを呼ぶ作りになっている。パケノバも同じ形にする。

- コマンドは、名前（例: `layer.blend.set`）、引数（JSON）、結果（JSON）を持つ。
- 画面のボタンも、MCP も、エージェントも、同じコマンドを呼ぶ。だから、どこから操作しても同じ結果になり、元に戻せる。
- コマンド 1 回が、元に戻す 1 回ぶん。まとめて呼んだもの（エージェントの 1 回の依頼、`command_batch`）は、1 回ぶんにまとめる。
- コマンドを呼んだことを、そのまま「操作の記録」として残せる（5 章）。

### はじめのコマンドの一覧（案）

名前は「対象.動作」。引数のレイヤーは番号ではなく、レイヤーごとの決まった印（`id`）で指す（並べ替えても変わらないように。いまは番号で持っているので、印を足す）。

| まとまり | コマンド |
|---|---|
| 案件 | `project.new`、`project.open`、`project.save`、`project.save_as`、`project.info` |
| 型 | `shape.set`（型の種類）、`shape.dimensions`（寸法、紙の厚さ、フラップ） |
| 素材 | `asset.import`（ファイルから）、`asset.list`、`asset.replace` |
| 柄 | `decal.add`（素材、文字、図形）、`decal.move`、`decal.resize`、`decal.rotate`、`decal.side`（表と裏）、`decal.delete`、`decal.duplicate`、`decal.align` |
| 文字と図形 | `text.set`（文字と書式）、`shape_art.set`（形と色） |
| レイヤー | `layer.list`、`layer.select`、`layer.rename`、`layer.visible`、`layer.lock`、`layer.blend.set`、`layer.opacity.set`、`layer.reorder`、`layer.clip` |
| グループ | `group.create`、`group.ungroup`、`group.open` |
| 調整 | `adjust.add`、`adjust.set`、`adjust.toggle`、`adjust.move`、`adjust.remove`、`adjustment_layer.add` |
| マスク | `mask.add`（すべて表示、被写体から、透明な部分から）、`mask.invert`、`mask.enable`、`mask.delete`、`mask.paint`（筆の線を点の並びで） |
| 表示 | `view.camera`（見る向き、平行投影）、`view.fold`（組み立て）、`view.open`（開け閉め） |
| 書き出し | `export.image`、`export.psd`、`export.pdf`、`export.gif` |
| 見る | `doc.inspect`（案件の状態を文字で）、`render.preview`（立体か展開図の絵を PNG で） |

作り方は段階を分ける。いまの操作は、画面の中の関数として書いてある。まずコマンドの入口（登録、引数の検査、元に戻す、記録）を作り、操作を 1 つずつその入口の下へ移す。移したものから、MCP とエージェントで使えるようになる。

## 2. MCP

PhotoCraft の作りに合わせる（PhotoCraft の `book/src/automation/mcp.md`）。

- パケノバに、画面なしのコマンドライン版 `pakenoba-cli` を足し、`pakenoba-cli mcp` で MCP サーバーとして動く（標準入出力。ネットワークの口を開けない）。
- 動き方は 2 つ。
  - 画面なし: `pakenoba-cli` の中で案件を開いて操作し、ファイルに保存する。
  - 開いている画面につなぐ: パケノバの画面で「AI からの操作を許す」を入れている間だけ、自分の PC の中だけの通信口を開き、合言葉（トークン）を設定のフォルダに置く。`pakenoba-cli mcp` は、それを見つけて画面へつなぐ。操作は画面にそのまま見え、元に戻せる。
- 道具（tools）は PhotoCraft と同じ 5 つを中心にする。
  - `command_list`: コマンドの一覧と、引数の形。
  - `command_run`: コマンドを 1 つ実行する。
  - `command_batch`: いくつかをまとめて実行する（元に戻すのは 1 回ぶん）。
  - `doc_inspect`: 案件の状態（型、寸法、レイヤーの並び、調整など）を JSON で。
  - `render_preview`: 立体（向きを指定できる）か展開図の絵を PNG で。AI が見た目を確かめるため。
- 読み物（resources）として `pakenoba://document`（案件の状態）と `pakenoba://commands`（コマンドの一覧）。
- 安全のために:
  - 「AI からの操作を許す」は、はじめは切ってある。
  - 読み書きできるフォルダを、使う人が決める（決めた外のファイルは読まない、書かない）。
  - 道具の説明や、案件の中の文字（柄の名前など）は、指示として扱わない。

## 3. エージェントの欄（画面の右の端）

### 見た目

- 画面のいちばん右に、開け閉めできる細い列を足す（プロパティとレイヤーの列の、さらに右）。閉じているときは、アイコンの帯だけ。
- 列の中は、上から、つなぎ先の選択、やりとりの一覧、入力の欄。
- エージェントが変えたことは、やりとりの中に「変えたことの一覧」（例:「柄 3 の描画モードを乗算に」）として出し、押すとそのレイヤーを選ぶ。1 回の依頼ごとに「元に戻す」ボタン。
- 動いている間は「止める」ボタン。止めたら、そこまでの変更は残し、元に戻すこともできる。

### 動き

1. 使う人が頼む（例:「正面のロゴをもう少し大きくして、帯を金色に」）。
2. パケノバは、頼みと一緒に、案件の状態（`doc.inspect` と同じ）と、いまの立体の絵（`render.preview`）を送る。
3. モデルは、コマンドを道具として呼ぶ。パケノバは実行して、結果（と、必要なら新しい絵）を返す。
4. 終わったら、モデルの説明と、変えたことの一覧を出す。この依頼の変更は、元に戻す 1 回ぶん。

### つなぎ先

| つなぎ先 | 方法 | 順番 | メモ |
|---|---|---|---|
| Anthropic | API（Messages API の道具の呼び出し） | 1 | キーを入れて使う |
| OpenAI | API（関数の呼び出し） | 1 | キーを入れて使う |
| GitHub Copilot | Copilot SDK（Rust 版がある。Copilot の CLI をアプリと一緒に配る形） | 2 | まだ技術プレビューで、変わることがある。Copilot の契約か、自分のキー（BYOK）が要る。1 回の依頼ごとに、プレミアムリクエストの枠を使う |
| ほかの AI のアプリ（Claude Desktop、VS Code の Copilot など） | MCP（2 章） | 1 | パケノバの側に欄は要らない |

- キーは、OS の鍵の保管庫（Windows の資格情報マネージャー、macOS のキーチェーン）に入れる。設定のファイルには書かない。
- 何を送るかを、欄の中に書いておく（案件の状態の文字と、プレビューの絵。素材の元のファイルは、頼まれたときだけ）。被写体を選択などの調整は、これまでどおり PC の中で動き、送らない。
- エージェントには、上書き保存とファイルの削除をさせない。書き出しは、使う人が決めたフォルダの中だけ。

## 4. 履歴: Git は入れない

Git を中に入れることは勧めない。

- `.pknb` は 1 つの ZIP で、中身の多くは絵（素材、マスク）。Git は、文字の差分には強いが、絵を細かく残し続けると大きくなる。
- パケノバには、もう軽く残せる仕組みがある。素材とマスクは、中身の印（SHA-256）を名前にして、同じ中身は 1 回しか入れない。設定のテキストは小さい。
- Git で管理したい人は、`.pknb` ごと自分の Git に入れればよい。

かわりに、2 つの軽い仕組みを入れる。

### 操作の記録

- コマンドを呼ぶたびに、1 行の記録を足す。いつ、誰が（人か、どのエージェントか）、何をしたか（コマンドの名前と、引数の要点）。
- 案件のファイルの中に `history/log.jsonl`（1 行 1 件の文字）として入れる。絵は入れない。
- 長くなりすぎないよう、新しい 2000 件だけ残す（設定で変えられる）。記録を残さない設定もある（はじめは記録する）。人に渡すときのために「記録を外して保存」も用意する。
- 画面では「履歴」の窓（「表示」→「履歴」）の「操作の記録」のタブに、新しい順に並べる（はじめはエージェントの欄の隣のタブと考えていたが、版と一緒に 1 つの窓にまとめた）。

### 版を残す

- 「版を残す」で、その時点の設定のテキストを `versions/<番号>.toml` として入れる。絵は、印で指すだけなので、増えるのは新しく足した絵やマスクだけ。
- 自動で残すのは、エージェントが変える直前（直近の 10 個まで）。名前を付けて残した版は消さない。
- 版を選ぶと、その時点の状態を開いて見比べられる。「この版に戻す」は、いまの状態を版として残してから戻す。
- 消した柄の絵も、版が指していれば残る。古い自動の版を消したときに、どの版からも指されなくなった絵を片付ける。

旧パケノバの版の管理（レビューと案の履歴のため）は引き継がないと決めている。今回のものは、エージェントの変更を見返して戻すための軽いもので、目的が違う。

## 9. 作ったもの（2026-11-24）

### コマンドの入口（`app/commands.rs`）

- コマンドの一覧（名前、AI に渡す説明、引数の形の JSON Schema、読むだけか）を 1 か所に持つ。はじめは 27 個: `doc.inspect`、`layer.list`、`layer.select`、`layer.rename`、`layer.visible`、`layer.lock`、`layer.blend.set`、`layer.opacity.set`、`layer.fill.set`、`layer.reorder`、`layer.clip`、`group.create`、`group.ungroup`、`decal.delete`、`decal.transform`、`adjust.add`、`adjust.set`、`adjust.toggle`、`adjust.move`、`adjust.remove`、`adjustment_layer.add`、`mask.add`、`mask.invert`、`mask.enable`、`mask.delete`、`edit.undo`、`edit.redo`。
- レイヤーには決まった印（`id`）を付けた。並べ替えても変わらない。案件のファイルにも入る。
- `run_command(誰が, 名前, 引数)` で 1 つ、`run_batch` でまとめて実行する。1 回のコマンドが元に戻す 1 回ぶん、まとめたものは全体で 1 回ぶん。途中で失敗したら、そこで止めて理由を返す（そこまでの変更は残り、元に戻せる）。
- 調整は、案件のファイルと同じ書き方の JSON で渡す（`{"kind": "levels", "black": 10, ...}`）。
- ロックしているもの、ないもの、知らない名前は、変えずに理由を返す。
- 同じ日に 15 個を足して 42 個にした（`app/commands_doc.rs`）: `project.info`、`project.new`、`project.open`、`project.save_as`、`shape.set`（型）、`shape.dimensions`（寸法とフラップ。元に戻す対象外）、`asset.list`、`asset.import`、`decal.add`（素材、付属の見本、文字、図形のどれか）、`text.set`、`shape_art.set`、`export.psd`、`export.pdf`、`render.preview`（展開図の絵を PNG で）。`doc.inspect` の柄には、文字と図形の中身も出す。あとで `version.list` と `version.keep` を足して 44 個。
- 案件を開く、作る、保存するは、案件の中身を変えないので、操作の記録には残さない。
- まだコマンドにしていないもの: 表示（向き、組み立て、開け閉め）、16:9 の画像と箱開け動画の書き出し（GPU で描くので、画面なしでは描けない）、立体の見た目の PNG、マスクを筆で描く、素材の差し替え。

### AI が使えるフォルダ

- 人以外（エージェントと MCP）がファイルを読み書きできるのは、「編集」→「環境設定」→「AI が使えるフォルダ」で許したフォルダと、MCP のサーバーを起動するときに `--allow` で渡したフォルダの中だけ（設定のファイルの `agent_folders`）。
- ファイルの場所は、はじめから書いた形（絶対パス）だけ受け付ける。リンクをたどった先も確かめる。
- すでにあるファイルには書かない（案件の保存も、書き出しも）。別の名前にしてもらう。
- 許したフォルダがなければ、どこにも書かず、許し方を返す。

### MCP のサーバー（`pakenoba mcp`、`app/mcp.rs`）

- 同じ `pakenoba` の実行ファイルに `mcp` を付けて起動すると、画面を出さずに MCP のサーバーとして動く。`pakenoba mcp [--allow <フォルダ>]... [案件.pknb]`。
- 標準入出力で、1 行 1 通の JSON-RPC 2.0（MCP の stdio の決まり）。ネットワークの口は開けない。MCP の版は 2025-06-18（2025-03-26、2024-11-05 にも答える）。部品（rmcp）は使わず、決まりのとおりに自分で書いた（非同期の部品を足さずに済む）。
- 道具は 5 つ: `command_list`、`command_run`、`command_batch`（まとめて 1 回ぶん元に戻す）、`doc_inspect`、`render_preview`（画像で返す）。読み物は `pakenoba://document` と `pakenoba://commands`。
- 呼んだ相手は、MCP の `clientInfo` の名前で記録に残る（例: `mcp:claude-desktop`）。
- 起動のときに渡した案件は、使う人が選んだものなので、許したフォルダの外でも開く。保存は `project.save_as` で、許したフォルダの中に新しい名前で。
- Claude Desktop の設定の例（`claude_desktop_config.json`）:

```json
{
  "mcpServers": {
    "pakenoba": {
      "command": "C:\\Program Files\\PAKENOBA\\pakenoba.exe",
      "args": ["mcp", "--allow", "D:\\Packages\\AI"]
    }
  }
}
```

- まだないもの: 開いている画面につなぐ形（画面で「AI からの操作を許す」を入れている間だけ、PC の中だけの通信口を開く）。いまは画面なしだけ。

### 画面の操作もコマンドを通す

- レイヤーの欄の操作（目、名前、ロック、描画モード、グループ、解除、クリップ、重なり順、消す、マスクの切り替え・反転・削除、調整の切り替え）は、コマンドを呼ぶ形にした。だから、人の操作も同じ記録に残る。
- ドラッグで続けて変えるもの（不透明度、塗り、調整の数値、柄を動かす・大きさ・向き）は、これまでの動きのまま、離したとき（数値の欄では変わるたび）に記録だけ足す。続けて同じものを変えた記録は 1 件にまとめる。
- 柄を置いたとき、調整やマスクを足したときも、記録に足す。

### 操作の記録

- 案件ごとに持ち、案件のファイルの `history/log.jsonl` に入る（新しい 2000 件）。
- 「表示」→「操作の記録」で、新しい順に、時刻、誰が（あなた、エージェント（名前）、MCP（名前））、何をしたか、どのレイヤーか、を出す。行にカーソルを乗せると、引数の中身。
- その窓の「操作を記録する」で切れる（設定に残る。はじめは記録する）。
- 「ファイル」→「記録を外して保存…」で、記録を入れずに名前を付けて保存する。保存すると、開いている案件の記録も消える（保存したファイルとそろえるため）。

### エージェントの欄（`app/agent.rs`）

- 上の帯の 2 段目の右の端「エージェント」（「表示」→「エージェント」でも）で、画面のいちばん右に欄を開く。デザインだけでなく、型と出力の工程でも使える。
- 欄の中は、上から、つなぎ先（Anthropic か OpenAI）とモデル、キーの状態、送るものの説明、やりとり、入力の欄（Ctrl+Enter で送る）、「止める」「新しい会話」。
- モデルは選べるほか、名前を打てる。はじめは Anthropic が `claude-sonnet-5-5`（ほかに `claude-opus-5-5`、`claude-haiku-5-5`）、OpenAI が `gpt-6.2-sol`（ほかに `gpt-6.2-astra`）。
- 送るのは、頼んだ文と、案件の状態（`doc.inspect` の文字）。モデルが `render_preview` を呼んだときは、展開図の見た目の絵も送る。素材のファイルそのものは送らない。欄にもそう書いてある。
- モデルには、MCP と同じ 5 つの道具を渡す。Anthropic は Messages API の道具の呼び出し（`tool_use` と `tool_result`。絵は `tool_result` の中に入れる）。OpenAI は Chat Completions の関数の呼び出し（道具の答えに絵を入れられないので、続けて使う人の言葉として絵を渡す）。
- API とのやりとりは別のスレッド。道具の呼び出しは画面のスレッドで実行する。1 回の依頼で、モデルとのやりとりは 30 回まで。
- 1 回の依頼で変えたことは、元に戻す 1 回ぶん。そのあとにほかの変更をしていなければ、欄の「この依頼を元に戻す」で戻せる（Ctrl+Z でも同じ）。
- 変えたことは、やりとりの中に「・描画モードを変えた　レイヤー 3」のように並べる。レイヤーの印を押すと、そのレイヤーを選ぶ。操作の記録には `agent:anthropic`、`agent:openai` として残る。
- 会話の続きは覚えておき、次の依頼でも前の流れを使う。つなぎ先を変えたとき、「新しい会話」を押したときに捨てる。
- 書き出しと保存は、AI が使えるフォルダの中だけで、上書きはしない（MCP と同じ決まり）。
- キーは「API キーを入れる…」で入れ、OS の鍵の保管庫（Windows の資格情報マネージャー、macOS のキーチェーン）に、サービス名 `PAKENOBA`、名前 `anthropic` か `openai` でしまう。設定のファイルには書かない。「消す」で保管庫から消す。保管庫にないときは、環境変数 `ANTHROPIC_API_KEY`、`OPENAI_API_KEY` も見る。
- キーを入れる窓は、PhotoCraft のパスワードの窓（craft-libs の `PasswordDialog`）と同じ形にした: 題の帯と閉じる ×、説明、「API キー」の欄（伏せ字。目のボタンで見せる・伏せる。開いたら欄に入力が向く）、右にそろえた「保存」（青）と「キャンセル」（Windows は保存が先）。Enter で保存、Esc で閉じる。キーのはじめの文字が違う（Anthropic は `sk-ant-`、OpenAI は `sk-`）ときは、注意を出す（止めはしない）。打った文字は、窓を閉じたらメモリーから消す（zeroize、MIT か Apache-2.0）。
- keyring は 3.6.3（MIT か Apache-2.0）。Windows では windows-sys、macOS では security-framework、Linux では linux-keyutils を使う（どれも MIT か Apache-2.0。byteorder は Unlicense か MIT）。Linux の linux-keyutils は、ログアウトすると消える（ずっと残す Secret Service は、D-Bus の部品が要るので入れていない）。
- 試験では、API の口を決まった答えを返すものに差し替えて、道具の呼び出し、絵の渡し方、1 回で元に戻ることを確かめた。本物の API にはつないでいない（キーがないため）。Windows での組み立て（鍵の保管庫の部分）も、まだ確かめていない。

### 版を残す（`app/versions.rs`）

- 「ファイル」→「版を残す…」で、名前を付けて、いまの案件を残す。エージェントに頼む前には、自動で残す（名前は「依頼の前: 頼んだ文のはじめ」）。自動の版は新しい 10 個だけ残し、名前を付けた版は消すまで残る。いちばん新しい自動の版と中身が同じなら、増やさない。
- 「表示」→「履歴」の窓の「版」のタブに、新しい順に並べる（名前、自動か、時刻、レイヤーの数）。
  - 「開く」: 新しいタブで開いて、いまの案件と見比べる。保存すれば、別の案件として残る。
  - 「この版に戻す」: 案件をその版の状態にする。戻す前の状態も自動の版に残し、Ctrl+Z でも戻せる（ただし、寸法だけの違いは元に戻すの対象外なので、戻した寸法は Ctrl+Z では戻らない。そのときは「戻す前」の自動の版に戻す）。操作の記録に「版に戻した」と残る。
  - ×: 確かめてから消す（元に戻せない）。
- 案件のファイルには `versions/001.toml` のように、版ごとの設定のテキストを入れ、一覧（名前、時刻、自動か）を `versions/index.json` に書く。素材とマスクは中身の印で入るので、いまの案件と同じ中身なら、ファイルは増えない。版は記録と版を持たない。読めない版は外して知らせ、案件そのものは開く。
- 版を残した、消した、も保存していない変更に数える（「*」が付く）。
- エージェントと MCP からも、`version.keep`（名前を付けて残す）と `version.list` を呼べる。
