# 新パケノバ 案件の保存の検討

- 作成日: 2026-11-21（同じ日に、全面的に書き直した）
- 状態: 6 章の決まりで進める（2026-11-22）。中核の読み書き、画面からの開く・保存、素材の差し替え、落ちたときの控えは実装済み（10 章）
- 関連: [方針メモ](concept.md)、[画面設計の検討](ui-design.md) の 4.6（素材の扱い）

いまのパケノバは、閉じると、置いた柄も取り込んだ素材も消える。案件をファイルに残す仕組みが要る。

## 0. この文書を書き直した理由

はじめの版は、入れ物の形（フォルダ）から提案していた。使う場面を先に洗い出していなかったので、「同じ素材を 3 つの案件で使ったら」「元を直したら」「1 つのファイルにできないのか」という質問のたびに、案が変わった。

進め方を、画面設計のときと同じにやり直した。使う場面を並べ、確認する点を決め、ほかのツールの作法を調べ、案を比べる。そのうえで、いま決めることと、あとで決めることを分ける。

## 3. ほかのツールの作法（2026-11-21 に、各社の説明で確認）

| ツール | 素材の持ち方 |
|---|---|
| Photoshop | 置いた素材を、埋め込むか、外のファイルへのリンクにするかを選ぶ（リンクは 2014 年の版から）。リンクは、元を直すと反映される |
| Illustrator | リンクか、埋め込み。リンクは元が変わると更新される。埋め込みは、元とのつながりがない |
| InDesign | リンクか、埋め込み。リンクは文書の外に置かれ、元を直すと反映される。埋め込むと、文書だけで完結する。「パッケージ」で、リンクのファイルを 1 つのフォルダに集める |
| Affinity | 文書ごとに「埋め込みを優先」か「リンクを優先」を選ぶ。素材ごとに切り替えられる。埋め込みが大きくなりすぎると、リンクへの切り替えを勧める。外で直されたリンクを自動で更新するかどうかは、設定で選ぶ。「収集」で、リンクのファイルを 1 つのフォルダに集める |
| Premiere Pro | 外のファイルを、場所と名前で指す。動かすと、つなぎ直しが要る。「プロジェクトマネージャー」で、使っているファイルを 1 か所に集める |
| Blender | 外のファイルを、相対パスで指すのが既定。「リソースをパック」で、ファイルの中に入れられる。重い動画は入れられない |
| Sketch | 1 つのファイルで、中身は ZIP。設定の JSON と、画像のフォルダが入っている。画像は元の大きさのまま持つ |
| Figma | ライブラリの部品が直されると、使っているファイルに「更新があります」と出る。中身を見てから、受け入れる |

読み取れること。

- 「埋め込み」と「リンク」の 2 つが、どのツールにもある言葉。デザイナーは、この 2 つの違いを知っている。
- リンクを使うツールは、必ず「集める」機能（パッケージ、収集）を持つ。リンクのまま人に渡すと欠けるため。
- 1 つのファイルの中身を ZIP にするのは、普通の作り（Sketch。PowerPoint の PPTX も同じ）。
- 素材集の更新を「知らせて、見てから受け入れる」のは、Figma のライブラリのやり方。

## 5. 結論

**Y（1 つのファイルに、すべて埋め込む）に、「差し替え」の操作を足した形にする。**

はじめの結論は「W を目標にして、作るのは Y から」だった。同じ日のうちに改めた。きっかけは、本人からの現場の話である。

- まわりのデザイナーは、Photoshop や Illustrator で、リンクをあまり使わない。リンクは、トラブルの元になるため。
- 埋め込んでおいて、素材を右クリックして別のファイルに差し替える、という手での更新のほうが、現場のデザイナーに合う。

W は、元の場所を覚えて知らせる仕組みで、4 つの案の中で状態がいちばん多かった（C6）。それを、使う人が実際には望んでいないなら、作らないほうがよい。S2 と S3（同じロゴを 3 つの案件で使い、直された）は、知らせではなく、差し替えの操作で解く。

差し替えの決まり。

- 素材の欄の素材か、箱の上の柄を右クリックして、「素材を差し替える」。ファイルを選ぶ。
- その素材を使っている柄が、すべて新しい絵になる。場所、向き、表と裏は、そのまま。幅はそのままで、高さは新しい絵の縦横の比に合わせる。
- 1 つの柄だけを別の素材にしたいときは、「この柄だけ差し替える」を選ぶ。
- 元に戻せる（Ctrl+Z）。
- 素材には、元のファイルの名前と、取り込んだ日時を覚えさせて、素材の欄に出す。どの版を入れてあるのかを、目で確かめられるようにする。

この形にする理由。

- 現場の使い方に合う（C4）。Photoshop の「コンテンツを置き換え」と同じ考え方で、説明が要らない。
- 何が起きるかを、使う人が完全に握れる（C3）。開いたら絵が変わっていた、も、更新に気づかなかった、も起きない。差し替えたものだけが変わる。
- いちばん単純で、テストで確かめやすい（C6）。

比較の表で、Y の「伝わらない」（S2、S3）は、差し替えの操作で補う。伝わらないことは、ここでは弱点ではなく、望まれている動きである。

Z を選ばない理由: リンクだけの素材は、素材集を動かしたり、人に渡したりすると、絵が出なくなる（S4、S5、S6）。「渡す前に埋め込む」という手順を、使う人が覚えていないといけない。W は、その手順が要らない。

X（フォルダ）をやめる理由: 利点は「素材を外のアプリでそのまま開ける」だったが、取り出して保存を見張る方法で足りる（Photoshop で、埋め込んだスマートオブジェクトを開いて直すときと同じ考え方）。フォルダは、保存の途中や同期の途中で中途半端な状態になりうる（S8、S11）。

## 6. 決めたこと

使う人に見える決まりは、次の 4 つだけ。1 から 3 は、2026-11-22 に決めた。4 は、異論が出ていないので、この形で進める（使ってみて合わなければ変える）。

1. 案件 1 つは、1 つのファイル。拡張子は `.pknb`（PaKeNoBa）。
2. 置いた素材は、案件のファイルの中に、元のファイルのまま入る。案件のファイルだけで、同じ絵が出る。外のファイルとのつながりは持たない。
3. 素材を新しくしたいときは、手で差し替える（5 章）。
4. 保存は、使う人が行う（Ctrl+S）。自動保存はしない。落ちたときのための控えは、別に取る。

拡張子について。

- 3 文字の案（`.pkn`、`.pnb`、`.pkb`）は、どれもほかのソフトの拡張子と重なる。`.pknb` は、拡張子の一覧サイトを探した範囲では、重なる相手が見つからなかった（網羅的な調べではない）。
- 旧パケノバの `.pakenoba` と `.pds-project` は使わない。中身の形式が別物なので、同じ拡張子にすると取り違える。
- パケノバは、拡張子ではなく中身（ZIP の中の設定のテキスト）を見て、自分の案件かどうかを判断する。

中の作り（私が責任を持って決め、あとから変えられるもの）。

- 中身は ZIP。設定のテキスト（TOML）が 1 つと、素材のファイル。
- 設定のテキストは `project.toml`。素材のファイルは `assets/` の下に入れる。展開図まるごとの絵（外のアプリで描いた PSD）も、元のファイルのまま、同じ場所に入れる。
- 素材のファイルは、中身の印（ハッシュ値。SHA-256）を名前にして入れる。同じ素材を 2 回入れても 1 つで済み、日本語のファイル名が化ける心配もない。元の名前は、設定のテキストに書く。
- 柄は、素材を、素材の一覧での番号で指す（中身の印では指さない）。差し替えで中身が変わっても、柄と素材のつながりはそのまま残る。
- 設定のテキストの先頭に、形式の版を書く。新しい版のパケノバは、古い版の案件を読める（C7）。知らない新しい版は、開かずに知らせる。
- 保存は、別の名前で書ききってから、元のファイルと入れ替える。途中で落ちても、前のファイルが残る（C1）。
- 柄の置き場所のパネルは、番号ではなく名前で書く。型紙を直して並びが変わっても、柄が別の面へ飛ばない。同じ名前のパネルがある型（角柱の「上のフラップ」など）では、何番目かも書く。パネルの名前は、形式の一部になる。あとで名前を変えるときは、古い名前からの読み替えを足す。
- 日時を書き込まない。同じ案件は、いつ保存しても同じバイト列になる（同期フォルダで、中身が同じなのに「変わった」と扱われない）。
- 読むときは、できるだけ開く。素材が欠けている、パネルが見つからない、といった部分的な傷は、その素材や柄だけを外して開き、何を外したかを知らせる（C2）。外して開いた案件は、元のファイルにそのまま上書きさせない（画面の側で、名前を付けて保存にする）。
- 寸法が範囲の外のときは、範囲の中へ寄せて、知らせる。

## 7. あとで決めること

作らないと決めたもの（要望が出たら、考え直す）。

- 元の場所を覚えて、「更新があります」と知らせる仕組み（案 W）。作るとしたら、素材集の名前と、その中での場所で覚え、中身の印が変わっていたら知らせ、見てから受け入れる形（Figma のライブラリと同じ）。この情報は、あってもなくても開ける形で足せるので、あとから入れても、いまの形式を壊さない。
- リンクだけで持つ素材（案 Z）。

素材集（コレクション）を作るときに決める。

- 素材集から差し替えるときの手順（素材集の新しい絵を、案件の素材の上へドラッグして差し替える、など）。
- 大きい素材（数百 MB の PSD）の扱い（S7）。入れたときに、案件のファイルが大きくなることを知らせる。それでも困るようなら、外を指すだけにする選択肢を考える。

詳しい編集を作るときに決める。

- 素材を外のアプリで直すときの、取り出し方と、保存の見張り方（S9）。

## 8. 実装の前に確かめること

| 確かめること | 方法 |
|---|---|
| 保存して開くと、同じ状態に戻る（型、寸法、柄の場所と向き、表と裏、素材） | 自動のテスト |
| 保存の途中で止まっても、前のファイルが壊れない | 自動のテスト（書きかけを作って確かめる） |
| 古い版の案件を、新しい版で開ける | 自動のテスト（版 1 の見本を残しておく） |
| 合わせて 300 MB ほどの素材を入れたときの、保存と開く時間 | 計って、数字を記録する。遅ければ、変わっていない素材を書き直さない工夫を入れる |
| Windows で、開く、保存する、のダイアログが動く。同期フォルダの上でも保存できる | 実機で見てもらう（Linux の仮想画面では確かめられない） |
| 足す部品（serde、toml、zip、rfd）のライセンスが、MIT または Apache-2.0 と両立する | 足すときに、入る版で確かめる |

## 10. 実装の状態（2026-11-22）

作る順の 1 番から 6 番まで、すべて済んだ。中核は `crates/pakenoba-core/src/project.rs`、画面は `crates/pakenoba-app/src/app/` の `file.rs`（開く、保存）、`assets.rs`（差し替え）、`recovery.rs`（控え）、`export.rs`（型紙の書き出し）、`library.rs`（「素材」の画面）、`settings.rs`（コレクションの登録）。

### 画面での動き

- 上の帯に「ファイル」のメニュー。開く（Ctrl+O）、保存（Ctrl+S）、名前を付けて保存（Ctrl+Shift+S）。ファイルを選ぶのは、OS のダイアログ。
- 上の帯とウィンドウの題に、案件の名前を出す。保存していない変更があるときは、名前のあとに「*」を付ける。保存していない案件の名前は「名前なし」。
- 保存していない変更があるかどうかは、型、寸法、柄、素材、展開図の絵から作る印を、最後に保存したときの印と比べて決める。柄を消してから元に戻すと、「*」も消える。視点や、表示の出し方は、変更に数えない（案件のファイルに入らないため）。
- 保存していない変更があるときに、別の案件を開く、またはウィンドウを閉じようとすると、「保存する」「保存しない」「キャンセル」を選ぶダイアログを出す。「保存する」を選ぶと、保存が終わってから、続きを行う。
- 保存は裏で進める。その間も画面は動く。保存の途中でウィンドウを閉じようとしたときは、保存が終わってから閉じる。
- 保存できなかったときは、理由をダイアログで知らせる。前に保存したファイルは、そのまま残る。
- 傷んだ案件は、読める部分だけを開いて、外したものの一覧を出す。そのときは「名前なし」の未保存の案件として開く（元のファイルに、そのまま上書きさせない）。
- 案件でないファイルは、開かずに知らせる。
- 案件のファイルをウィンドウに落としても、開ける。起動するときに、案件のファイルの場所を渡しても、開ける（ファイルをパケノバに関連付けて、ダブルクリックで開くときの渡し方）。
- 取り込んだ画像（PNG）と、展開図まるごとの絵（PSD）は、元のファイルの中身のまま持ち、案件のファイルに入れる。同じ中身の画像をもう一度取り込んだときは、素材を増やさずに、すでにあるものを使う。

### 素材の差し替え（2026-11-22）

5 章の決まりどおりに作った。

- 入口は 4 つ。箱や展開図の上の柄を右クリック、レイヤーの欄の柄を右クリック、素材の欄の素材を右クリック、素材の欄の下の大きな絵の「差し替える…」。
- 柄の右クリックのメニューには、「素材を差し替える…（n か所）」「この柄だけ差し替える…」「消す」が出る。付属の見本（ロゴ、帯）を使っている柄では、「この柄を画像に差し替える…」だけ。
- 「素材を差し替える」は、その素材を使っている柄を、すべて新しい絵にする。素材の名前も、新しいファイルの名前になる。
- 「この柄だけ差し替える」は、新しい画像を素材の欄に足して、その柄だけを入れ替える。同じ中身の素材がすでにあれば、それを使う。
- どちらも、場所、向き、表と裏、幅はそのまま。高さは、新しい絵の縦横の比に合わせる。
- 元に戻せる（Ctrl+Z）。元に戻すと、素材の名前と中身も戻る。そのために、元に戻すための記録に、この案件の素材の一覧も入れた（絵の中身は共有しているので、重くならない）。
- 選べるのは PNG だけ（柄にできる画像が、いまは PNG だけのため）。読めないファイルを選んだときは、何も変えずに知らせる。
- 素材の欄の下に、取り込んだ日時を、その土地の時刻で出す。どの版を入れてあるのかを、目で確かめるため。日時は、時差つきで覚える（例: `2026-11-22T10:05:12+09:00`）。

自動のテストで、すべての柄が変わること、幅と高さ、元に戻すとやり直す、柄だけの差し替え、同じ中身の素材を使い回すこと、読めないファイルと付属の見本では変えないことを確かめた。クラウドの画面で、右クリックのメニューから差し替えるところまで確かめた。

### 落ちたときの控え（2026-11-22）

- 保存していない変更があるあいだ、30 秒ごとに控えを書く（前の控えから変わっていなければ書かない）。書くのは裏の仕事で、画面は止まらない。
- 控えの場所は、使う人のデータのフォルダの中。Windows では `%LOCALAPPDATA%\pakenoba\recovery`、macOS では `~/Library/Application Support/pakenoba/recovery`、Linux では `~/.local/share/pakenoba/recovery`。案件のフォルダには書かない（同期フォルダを汚さない、案件のファイルと取り違えない）。
- 控えは、案件のファイルと同じ形（`.pknb`）。横に、元の案件の場所と日時を書いたテキストを置く。どちらも、書ききってから入れ替える。
- 起動している間は、自分の控えに鍵（OS のファイルの鍵）をかけておく。次に起動したとき、鍵の外れた控えだけを「前回、保存しないまま終わった案件」として見せる。パケノバを 2 つ起動していても、動いている方の控えを取り違えない。
- 見せるダイアログでは、控えごとに「開く」「捨てる」。「あとで決める」を選ぶと、控えは残し、次に起動したときにまた聞く。
- 開いた控えは、元の案件の場所につなぎ、保存していない状態にする。保存すると、元の案件のファイルが新しくなる。元のフォルダがなくなっていれば、名前なしにする。開いた控えは、この起動の控えとして引き継ぐ（もう一度落ちても残る）。
- 保存したとき、元に戻して変更がなくなったとき、ふつうに閉じたとき（「保存しない」を選んだときを含む）は、控えを消す。

自動のテストで、動いている起動の控えがほかの起動から見えないこと、落ちたあとに開いて同じ柄に戻ること、捨てた控えが消えること、控えのない鍵が片付くことを確かめた。クラウドの画面で、柄を消して控えが書かれ、強制終了してから起動すると聞かれ、開くと元の場所につながること、保存と、元に戻すと、閉じるときに控えが消えることを確かめた。

### 裏の柄の書き出し（2026-11-22）

- 「出力」の「型紙を PSD で保存…」で、保存先を OS のダイアログで選ぶ（これまでは、起動したフォルダに決まった名前で書いていた）。はじめの名前は「案件の名前_型紙.psd」。
- 紙の裏に柄があれば、裏の型紙も、同じ場所に「_裏」を付けた名前で保存する（例: `箱_型紙_裏.psd`）。
- 裏の型紙は、裏から見た向き（表を左右に裏返した向き。「裏」の表示と同じ向き）で書く。紙を裏返して刷るときの、そのままの向き。
- 裏の型紙のレイヤーは、下から「紙の裏」、裏に置いた柄（1 つにつき 1 レイヤー）、「ガイド（切り線、折り線）」。のりしろの斜線は入れない。
- 裏の型紙を読み込んで、紙の裏の絵にすることは、まだできない（展開図まるごとの絵は、表だけ）。

### 素材集（コレクション）と「素材」の画面（2026-11-22）

- 素材集は、フォルダを登録するだけ。フォルダの中身は動かさない、書き換えない。登録は「素材」の画面の左の「＋ 登録…」から、OS のダイアログでフォルダを選ぶ。右クリックで「読み直す」「登録を外す」。
- 登録したフォルダの一覧は、案件ではなくアプリの設定として、使う人のデータのフォルダに書く（Windows では `%LOCALAPPDATA%\pakenoba\settings.toml`。控えのフォルダと同じ場所の隣）。人が読める TOML。読めない設定ファイルは、上書きせずに残す（その回は覚えない）。
- フォルダの中は、PNG だけを、4 階層の深さまで、5000 個まで探す。隠しフォルダは見ない。フォルダが見つからないとき（外付けのドライブを外した、など）は、そう出して「読み直す」か「登録を外す」を選べる。
- 一覧の絵は、別のスレッドで作る。見えているマスの分だけ作り、新しく頼んだものから先に作る。覚えておく絵は 600 枚までで、超えたら、しばらく見ていないものから捨てる。
- 取り込むと、画像の中身を案件に写す（案件のファイルだけで開けるように。6 章の決めごとどおり）。同じ中身がすでに案件にあれば、増やさない。取り込み済みかどうかは、中身の印（SHA-256）で見る。名前や場所が違っても、中身が同じなら取り込み済み。
- 取り込みは、元に戻せる。取り込むだけで、箱には置かない。置くのは、デザインの工程の左の欄からドラッグ。
- 7 章の「素材集から差し替えるときの手順」と「大きい素材（PSD）の扱い」は、まだ決めていない。いまの差し替えは、OS のダイアログでファイルを選ぶ形だけ。素材集にも、PSD はまだ並ばない。

### 8 章の確かめの結果

| 確かめること | 結果 |
|---|---|
| 保存して開くと、同じ状態に戻る | 自動のテストで確認。差し込み箱、ゲーブル型、ピロー型、三角柱、六角柱、八角柱で、すべてのパネルに柄を置いて、表と裏、素材、付属の見本を混ぜた案件が、同じ状態に戻る。数は、30 万通りのビットの並びで、書いて読み戻すとビットの並びまで元に戻ることを確認 |
| 保存の途中で止まっても、前のファイルが壊れない | 自動のテストで確認。半分だけ書いて失敗させても、前のファイルがそのまま残り、書きかけのファイルは残らない。前に止まったときの書きかけが残っていても、開けるし、保存もできる |
| 古い版の案件を、新しい版で開ける | 版 1 の見本（`crates/pakenoba-core/tests/data/v1-sample.pknb`）を残し、それを開くテストを置いた。形式を変えたあとも、このテストが通ることで確かめる。新しすぎる版（版 2）は、開かずに知らせることも確認 |
| 傷んだファイル | 自動のテストで確認。途中で切れたファイル、1 バイト化けたファイルで落ちない。素材が欠けている、素材の中身が傷んでいる、柄の指定が正しくない、のそれぞれで、その部分だけを外して開く |
| 300 MB の素材での時間 | 計った（下の表） |
| 画面からの開く、保存 | クラウドの画面（Linux の仮想画面）で、キーとボタンを押して確認。保存、名前を付けて保存、開く、未保存の確認（保存する、保存しない）、閉じるときの確認、元に戻すと「*」が消えること、傷んだ案件、案件でないファイル、保存できない場所。開いてそのまま別の名前で保存したファイルは、元と 1 バイトも違わなかった |
| Windows でのダイアログ、同期フォルダ | まだ。クラウドでは、OS のダイアログを出せないので、答えを先に渡す形で確かめた。ダイアログそのものと、閉じるときの確認は、実機で見てもらう |
| 足す部品のライセンス | 確認した（下） |

300 MB（圧縮の効かない PNG 相当 200 MB と、圧縮する PSD 相当 100 MB）を入れた案件での時間。クラウドの Linux で、最適化した版で 1 回計った値。Windows の実機では違う値になる。

| 操作 | 時間 |
|---|---|
| 取り込み（中身の印を作る。にせのデータを作る時間を含む） | 0.5 秒 |
| 保存 | 2.2 秒 |
| 開く | 0.3 秒 |

保存の 2 秒あまりは、押してから待つ長さとして気になる。画面では、保存を裏で進めて、その間も画面が止まらない形にした。それでも遅ければ、変わっていない素材を書き直さない工夫を入れる。

足した部品と、ライセンス（実際に入る版で確認）。

| 部品 | 版 | ライセンス |
|---|---|---|
| serde | 1.0.229 | MIT または Apache-2.0 |
| toml | 1.2.2 | MIT または Apache-2.0 |
| zip | 9.8.1 | MIT |
| sha2 | 0.11.1 | MIT または Apache-2.0 |
| rfd（OS のダイアログ） | 0.18.0 | MIT |
| chrono（その土地の時刻） | 0.4.45 | MIT または Apache-2.0 |

画面のほうにも、設定（コレクションの登録）を書くために、serde と toml を足した。中核と同じ版で、ライセンスも同じ。

これらが連れてくる部品は、ほとんどが MIT または Apache-2.0。それ以外は、winnow（MIT）、zlib-rs（Zlib）、memchr（Unlicense または MIT）、constant_time_eq（CC0-1.0、MIT-0、Apache-2.0 のどれか）で、どれも「MIT または Apache-2.0」での公開と両立する。zip は、圧縮（deflate）だけを有効にした。暗号化と、ほかの圧縮形式は入れていない。

### まだ入っていないもの

- 「新しい案件」（いまは、アプリを起動し直す）と、最近使った案件の一覧。メニューバーを作るときに足す。
- 展開図まるごとの絵（PSD）の差し替え。いまは、読み込み直すと入れ替わる（元に戻すの対象外）。
- PNG 以外の画像（PSD、JPEG）を、柄の素材にすること。
- 保存の進み具合の表示は、「保存しています…」の 1 行だけ。
- 素材集の「最近使ったもの」と、タグ。素材集の中から、案件の素材へドラッグして差し替えること。
