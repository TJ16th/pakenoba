# 新パケノバ 案件の保存の検討

- 作成日: 2026-11-21
- 状態: 提案（未決定）。実装はまだ
- 関連: [方針メモ](concept.md)、[画面設計の検討](ui-design.md) の 4.6（素材の扱い）

いまのパケノバは、閉じると、置いた柄も取り込んだ素材も消える。案件をファイルに残す仕組みが要る。コレクション（フォルダの登録）、素材と柄のリンク、裏の柄の書き出しも、これが土台になる。

決めることが多いので、案と、決めてほしいことをまとめる。

## 1. 案: 案件は「フォルダ」にする

案件 1 つを、フォルダ 1 つにする。中身は、人が読めるテキストのファイル 1 つと、素材のファイル。

```
おかしの箱/
  おかしの箱.pakenoba      案件のファイル（テキスト）
  assets/                  この案件の素材（PNG、PSD、SVG など。元のファイルのまま）
    logo.png
    pattern.png
  exports/                 書き出したもの（型紙の PSD、画像、動画）
```

方針メモで決めたこと（「素材はプロジェクトフォルダ内の独立したファイルとして持つ」「外部アプリで開いて、保存を検知して箱に反映」）に、そのまま合う形。

| 案 | 良い点 | 弱い点 |
|---|---|---|
| フォルダ（この案） | 素材を Photoshop などで直接開ける。保存を検知して反映できる。Git で差分が見える。壊れても中身を取り出せる | 人に渡すときは、フォルダごと（または zip にして）渡す。フォルダの中を手で動かされると、リンクが切れる |
| 1 つのファイル（zip の中に全部） | 渡しやすい。1 つ動かせば済む | 素材を外部アプリで開くたびに、取り出して戻す仕組みが要る。差分が見えない |

推奨は、フォルダ。あとから「1 つのファイルに固めて書き出す、読み込む」を足せる（逆は難しい）。

## 2. 案件のファイルの中身

```toml
format = 1                      # 形式の版。読めない版は、開かずに知らせる

[shape]                         # 型と寸法
kind = "tuck_box"
width = 120.0
depth = 60.0
height = 160.0
thickness = 0.5

[[decal]]                       # 柄。上のものほど下に重なる
asset = "assets/logo.png"       # 素材への、フォルダの中での道のり
side = "front"                  # front（表）か back（裏）
panel = "正面"                  # 置かれているパネルの名前
at = [0.5, 0.6]                 # パネルを囲む四角の中での位置（0〜1）
size = [46.0, 46.0]             # mm
angle = 0.0                     # 度

[view]                          # 画面の状態（なくても開ける）
shown = ["solid", "front"]
```

- 形式は TOML を提案する。人が読めて、Rust で扱いやすく、コメントを書ける。JSON でもよい。
- パネルは、番号ではなく名前で持つ。型紙を直してパネルの並びが変わっても、柄が別の面へ飛ばない。
- 付属の見本（ロゴ、帯）は、`asset = "builtin:logo"` のように書く。
- 素材は、同じファイルを何度置いても 1 つ。素材のファイルを直すと、それを使っているすべての柄に反映する（4.6 のリンク）。
- 展開図まるごとの絵（PSD）も、素材として `assets/` に置き、`[sheet] art = "assets/sheet.psd"` で指す。

## 3. 画面

- 上の帯の左に、案件の名前を出す。保存していない変更があるときは、名前の横に印。
- 「開く」「保存」「名前を付けて保存」は、OS のダイアログを使う（画面設計の 7 章の決定）。Ctrl+O、Ctrl+S。
- 起動したとき: 最後に開いていた案件を開く。なければ、名前のない新しい案件。
- 閉じるとき: 保存していない変更があれば、確認する（作業を止めるダイアログを使ってよい、数少ない場面）。
- 自動保存は、はじめは入れない。まず、落ちたときのための控えを、案件のフォルダの外に、一定の間隔で書く。

## 4. 足す部品

| 部品 | 用途 | ライセンス（記憶による。未確認） |
|---|---|---|
| serde、toml | 案件のファイルの読み書き | MIT または Apache-2.0 |
| rfd | 開く、保存する、フォルダを選ぶ、の OS のダイアログ | MIT |
| notify（後の段階） | 素材のファイルが外で保存されたことの検知 | CC0-1.0 |

ライセンスは、今回は調べ直していない。足すときに、`Cargo.lock` に入る版で確かめる。rfd のダイアログは、Linux の仮想画面では動かして確かめられないので、Windows での確認が要る。

## 5. 決めてほしいこと

1. 案件は「フォルダ」でよいか（1 つのファイルに固める形は、あとから書き出しとして足す）。
2. 案件のファイルの拡張子は `.pakenoba` でよいか。
3. 形式は TOML でよいか。
4. 起動したとき、最後の案件を開く、でよいか。
5. 自動保存は入れず、まずは「落ちたときの控え」だけ、でよいか。

## 6. 作る順（案）

1. 中核に、案件の読み書き（型、柄、素材への道のり）。往復のテスト。
2. 画面に、開く、保存する。素材を `assets/` へ写す。
3. コレクション（登録したフォルダの一覧。設定の保存が要るので、ここで設定ファイルも作る）。
4. 素材のファイルの保存の検知と、柄への反映。
5. 裏の柄の書き出し（型紙の PSD を、表と裏の 2 つに）。
