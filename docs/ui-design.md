# 新パケノバ 画面設計の検討

- 作成日: 2026-11-21
- 状態: 一部決定（10 章）。決まった内容は、この文書をそのまま「画面のガイド」として使う
- 関連: [方針メモ](concept.md)

いまの画面（`pakenoba-app`）は、試作の操作部品を 3 つのタブに振り分けただけの仮の並びで、設計したものではない。この文書で、画面の並びと、文字やツールチップなどの方針を決める。

## 1. デザインガイドは使うか

使う。ただし、既製のデザインシステムをそのまま採用するのではなく、この文書をパケノバのガイドとして育てる。

| 材料 | 使い方 |
|---|---|
| 旧パケノバのペルソナとシナリオ（`user-scenarios.md`）、設計原則、文字サイズの決まり | 土台にする。レビュー機能をやめたぶんを読み替える（2 章） |
| PhotoCraft と VectorCraft の作法 | 配置、ショートカット、テーマを合わせる。同じ egui で作るので、見た目の値も合わせやすい |
| Photoshop、Illustrator、Affinity など、従来のクリエイティブツールの作法 | 配置と操作の基準にする（3 章） |
| 外部のデザインシステム（Adobe Spectrum など） | 参考にとどめる。egui では部品をそのまま使えない |

確認できていないこと: PhotoCraft に、独立したデザインガイドの文書があるかどうか。README からは見当たらなかった。テーマの色や文字サイズの実際の値は、ソースを読んで確かめる必要がある。

## 2. ペルソナとシナリオ

旧パケノバのペルソナは、利用観察ではなく、仕様と想定業務から作った仮説だった。新パケノバでも仮説のまま引き継ぎ、次のように読み替える。P4 は今回足した仮説。

| ペルソナ | 人物 | 新パケノバでの位置づけ |
|---|---|---|
| P1 森川 彩 | パッケージのグラフィックデザイナー。2D 制作に習熟。3D ソフトは使わない。納期が短い | 主役。この人が迷わないことを最優先にする |
| P3 高橋 健 | 生成AI（ComfyUI）を使うデザイナー | 準主役。生成AIのパネルの利用者 |
| P2 佐藤 直樹 | アートディレクター。操作はしない | 利用者ではなく、出力を見る相手。出力の品質と条件の統一に効く |
| P4 はじめての人 | GitHub で見つけて試す個人。説明は読まない | 無料公開にしたことで増える層。最初の 1 分で箱が出ないと離れる |

### シナリオ

| 番号 | シナリオ | 主なペルソナ | 画面に求めること |
|---|---|---|---|
| N1 | 型を選び、寸法を入れて、箱を見る | P4、P1 | 起動して迷わず型を選べる。寸法は mm で打てる。結果がすぐ箱に出る |
| N2 | ロゴや写真を置き、面をまたいで合わせる | P1 | 置く、動かす、大きさを変える、回す、を箱の上で直接できる。数値でも合わせられる |
| N3 | Photoshop や Affinity と行き来する | P1 | 型紙を出す、絵を戻す、が 1 手ずつ。レイヤーの対応が見える |
| N4 | 素材を細かく直す | P1 | 柄から PhotoCraft や VectorCraft を開ける。保存したら箱に戻る |
| N5 | 生成AIで背景の候補を作って選ぶ | P3 | 候補を箱の上で見比べ、残すものだけを柄にする |
| N6 | 上司や客に見せる画像と動画を出す | P1（見るのは P2） | ボタン 1 つ。カメラと背景がそろった、きれいな絵が出る |
| N7 | 厚紙に印刷して、自分で組む | P1 | 実寸の型紙。のりしろと折り線が分かる。組み立てと開け方を画面で確かめられる |

### シナリオから引き継ぐ原則

旧パケノバの設計原則のうち、新パケノバでも効くもの。

1. 3D の専門用語を知らなくても、2D 制作の言葉で操作できる（面、展開図、折り線。UV やメッシュとは言わない）
2. 高度な機能は段階的に見せ、最初の確認までを短くする
3. 操作と結果を同じ場所に置き、調整と確認の往復を短くする
4. 制作物の色の判断を優先し、画面の色と飾りは、必要な状態の表示に限る
5. 製造用のデータと誤認させない
6. 不正な入力や失敗で、最後の正常な状態を失わない

## 3. 従来のクリエイティブツールの作法

Photoshop、Illustrator、Affinity、Figma、Premiere、3D の塗りツールに共通する作法。記憶にもとづく整理で、今回あらためて各ソフトを確かめたものではない。

| 作法 | 内容 |
|---|---|
| 左に道具 | アイコンだけの細い帯。1 文字のショートカット（V で選択、T で文字、など） |
| 上に、選んだ道具の設定 | 道具を変えると、上の帯の中身が変わる |
| 右に、プロパティとレイヤー | 選んだものの数値と、重なりの一覧。目のアイコンで表示、鍵でロック |
| 中央は制作物だけ | 説明文を置かない。余白は制作物のために使う |
| メニューバー | すべての機能がメニューから見つかる。ショートカットはメニューで覚える |
| 直接操作 | 角をつかんで大きさ、外側で回転。Shift で比率を保つ、Alt で中心から |
| 右クリックのメニュー | その場で使える操作だけ |
| 元に戻す | Ctrl+Z。確認のダイアログを出すより、戻せるようにする |
| 表示の操作 | スペースで手のひら、ホイールで拡大縮小、Ctrl+0 で全体 |
| 下に時間軸 | 動きを扱うソフトは、下に再生の帯を置く |

## 4. 画面の並びの候補

### 案 A: 工程タブ型（いまの骨組みの延長）

上のタブで「型」「デザイン」「出力」を切り替える。左の広い欄に、その工程の操作が上から順に並ぶ。右の欄と道具の帯はない。Lightroom や、旧パケノバに近い。

### 案 B: クリエイティブツール型

Photoshop や Affinity と同じ並び。メニューバー、上の設定の帯、左の道具の帯、右にプロパティとレイヤーと型のパネル。工程の切り替えはなく、すべてがいつでも使える。

### 案 C: 折衷型（工程の切り替え ＋ 道具とパネル）

上のタブで工程を切り替えるが、中の配置は従来ツールの作法に合わせる。左に道具の帯、右にプロパティとレイヤー、下に組み立てと開け閉めの帯。工程を変えると、左右に出るものが入れ替わる。中央の立体は変わらない。

### シナリオでの検証

◎ はそのシナリオに向く、○ は問題ない、△ は弱い。

| シナリオ | 案 A | 案 B | 案 C |
|---|---|---|---|
| N1 型を選んで箱を見る | ◎ 順に進める | △ 型のパネルを探す必要がある | ◎ 最初の工程が「型」 |
| N2 柄を置いて合わせる | △ 数値と一覧の置き場がない | ◎ いつもの配置 | ◎ デザインの工程は案 B と同じ配置 |
| N3 外部ソフトと行き来 | ○ | ◎ レイヤーの対応が見える | ◎ |
| N4 素材を細かく直す | ○ | ◎ PhotoCraft と同じ感覚 | ◎ |
| N5 生成AI | ○ 左の欄に置ける | ○ パネルが 1 つ増える | ○ デザインの工程のパネル |
| N6 見せる出力 | ◎ 出力の工程がある | △ 書き出しのダイアログに押し込む | ◎ 出力の工程がある |
| N7 型紙と組み立て | ○ | △ 組み立ての操作の置き場が弱い | ◎ 下の帯に常にある |

### 作法での検証

| 作法 | 案 A | 案 B | 案 C |
|---|---|---|---|
| 左に道具、右にプロパティとレイヤー | △ ない | ◎ | ◎ |
| 中央は制作物だけ | △ 左の欄が広く、説明文が多い | ◎ | ◎ |
| 直接操作と数値の併用 | △ | ◎ | ◎ |
| メニューバーとショートカット | ○ 足せる | ◎ | ○ 足す |
| 画面を切り替えても配置が動かない | ◎ | ◎ 切り替えがない | ○ 左右の中身は入れ替わる |

### 良い点と弱い点

| 案 | 良い点 | 弱い点 |
|---|---|---|
| A | 作るのが早い。初めての人が順に進める。出力の置き場がはっきりしている | デザインの作業が窮屈。Photoshop に慣れた手に合わない。「既存のツールに寄せる」という決定に合わない |
| B | デザイナーの手に最も合う。PhotoCraft と並べて違和感がない | 型を決める、出力する、というパケノバ固有の流れが埋もれる。初めての人が最初の一歩で迷う。パネルが多く、立体が狭くなる |
| C | 流れの分かりやすさと、手になじむ配置の両方を取れる。工程ごとに出すものを絞れるので、立体を広く使える | 作る量がいちばん多い。工程を変えると左右の中身が変わるので、「さっきのパネルはどこ」が起きうる |

### 推奨

案 C。方針メモの決定（既存のツールに寄せる。型紙を決める → 配置する → 書き出す、の流れは保つ）の両方を満たすのは、この案だけ。

案 C の弱い点には、次の手当てをする。

- 工程を変えても、同じ種類のものは同じ場所に出す。左は「選ぶ・道具」、右は「選んだものの設定」、下は「動き」。中身は変わっても役割は変えない。
- デザインの工程に、型の寸法へ戻る入口を置く（右のパネルの上に、型の名前と寸法を小さく出す）。往復で迷わないようにする。
- 作る順は、デザインの工程を先にする。いちばん長く使う場所で、作法との差が出やすい。

工程ごとの配置。

| 工程 | 左 | 中央 | 右 | 下 |
|---|---|---|---|---|
| 型 | 型の一覧（箱の絵で選ぶ） | 立体 | 寸法、紙の厚み、型紙の検査 | 開け閉め、組み立て（4.5。立体の表示のすぐ下） |
| デザイン | 道具の帯（選ぶ、文字、図形、生成AI、手のひら）と、素材の欄 | 立体、表、裏（それぞれ出す、隠す） | プロパティ、レイヤー | 同じ |
| 出力 | 出力の種類（スライド用の画像、箱開け動画、棚、型紙） | 仕上がりの見え方 | その出力の設定 | 動画のときは時間軸 |

## 4.5 デザインの工程の仕様（案）

### 上の帯

左で選んだ道具に応じて、中身が変わる。Photoshop のオプションバーと同じ役割。右端の表示の切り替えだけは、道具に関係なく常に出す。

| 道具 | 上の帯に出るもの |
|---|---|
| 選択 | 整列と等間隔（2 つ以上を選んだとき）、重なり順、反転 |
| 文字 | フォント、大きさ、色、揃え |
| 図形 | 塗り、線 |
| 手のひら | なし |

### 整列の置き場

2026-11-21 に、Adobe の説明と解説記事で確かめた。

| ソフト | 整列の置き場 |
|---|---|
| Photoshop | 移動ツールを選ぶと、上のオプションバーに整列と分布のアイコンが出る。レイヤーを 2 つ以上選ぶと使える。独立したパネルは標準にはない |
| Illustrator | 独立した「整列」パネルがある（ウィンドウ > 整列、Shift+F7）。オブジェクトを選ぶと、上のコントロールパネルとプロパティパネルにも出る |

パケノバでは、上の帯（選択の道具のとき）と、右のプロパティの欄の両方に置く。独立したパネルは作らない。パネルを増やすと、立体が狭くなるため。

### 文字の設定の置き場

Photoshop は、文字ツールを選ぶと、上のオプションバーにフォント、スタイル、大きさ、揃え、色が出る。細かい設定は、文字パネルと段落パネルにある。2020 年の版からは、プロパティパネルにも同じ設定が出る。

パケノバでは、基本（フォント、大きさ、色、揃え）を上の帯に、細かい設定（字間、行送り、文字の幅）を右のプロパティの欄に置く。文字パネルと段落パネルは作らない。

### 詳しい編集への移り方

柄をダブルクリックする（右の欄の「編集」ボタン、Ctrl+E でも同じ）。

- 最初の段階: その柄のファイルを、外部アプリで開く。画像は PhotoCraft、ベクターは VectorCraft が既定。設定で Photoshop や Affinity に変えられる。向こうで保存すると、箱に自動で反映する。編集中の柄は、レイヤーに印を付ける。
- その後: 中央が柄の編集画面に切り替わり、PhotoCraft の道具とパネルが出る。上に「箱に戻る」を置く。箱は小さい窓で見え続ける。

### 表示の切り替え

2026-11-21 に改めた。はじめの案は「立体、表、裏、並べる」の 4 つから 1 つを選ぶ形だった。「並べる」だけが並べ方で、ほかの 3 つは見るものなので、粒度がそろっていなかった。

上の帯の右端に、「立体」「表」「裏」の 3 つのボタンを置く。どれも同じ種類のボタンで、その表示を出すか隠すかを切り替える。並べ方は選ばせない。出ている表示の組み合わせから決まる。

| 表示 | 内容 |
|---|---|
| 立体 | 箱。下の帯で、組み立てと開け閉めができる |
| 表 | 展開図の表（印刷面）。いつも平らで、正面を向いている。mm の定規が出る |
| 裏 | 展開図の裏。表を左右に裏返した向きで見せる |

| 出ている表示 | 並べ方 |
|---|---|
| 1 つ | 中央いっぱい |
| 立体と、表か裏のどちらか | 左に立体、右に展開図 |
| 表と裏 | 上下に並べる。展開図は横長のことが多いので、縦に積むほうが大きく見える |
| 3 つ | 左に立体を大きく、右に表と裏を上下に |

- 少なくとも 1 つは出ている。最後の 1 つは隠せない。
- はじめは立体だけ。出し方は、案件ごとに覚える。
- 1、2、3 のキーで、その表示だけにする（立体だけ、表だけ、裏だけ）。Alt を押しながらボタンを押しても同じ。「立体から表へ切り替える」が 1 手で済む。
- どの表示でも、柄を選べて、動かせる。選択は連動する。
- 1 つの表示で柄にカーソルを置くと、ほかの表示の同じ場所を光らせる。表と裏は向きが逆なので、対応が分からなくなるのを防ぐ。
- 表と裏は、立体の折り具合とは関係なく、いつも平らな展開図を見せる。立体の組み立てと開け閉めは、下の帯で動かす（次の節）。

### 下の帯（開け閉めと組み立て）

別々の 2 つの動きを置く。どちらも立体の表示に効く。型の工程とデザインの工程の両方に出す。

置き場は、立体の表示のすぐ下（2026-11-21 に改めた。はじめは画面全体の下の帯だったが、展開図の表示の下まで伸びていて、どの表示の操作なのかが分かりにくかった）。立体の表示が狭いときは、2 行に分ける。立体の表示を隠しているときは、出さない。

| 動き | 内容 | デザイン中の使いみち |
|---|---|---|
| 開け閉め | 組み上がった箱を、買った人が開ける、閉める動き（フタ、差し込み、ゲーブルの屋根など） | 開けたときに何が見えるか、フタの裏や内側の柄、開け口をまたぐ柄のつながりを見ながら置く |
| 組み立て | 平らな展開図から、折って、のりしろを貼って、箱になるまで | 展開図のどこが箱のどこに来るか、のりしろに隠れる場所、貼り合わせをまたぐ柄を確かめる |

- 開け閉めを左に、大きく置く。デザイン中にいちばん動かすため。スライダーの左に、押すたびに「開ける」「閉じる」が切り替わるボタンを 1 つ付ける（文字は、押したときにすること。動いている途中で押せば、折り返す。2026-11-24 に、両端の 2 つのボタンから改めた）。
- 底も開く型（差し込み箱、角柱、ゲーブル型）では、「底」の開け閉めを、そのとなりに別に置く（2026-11-22）。上と底は、別々に動かせる。実物の箱は底からも開けられ、底の差し込みと内側のフラップも柄の置き先なので、立体の表示で確かめられるようにした。
- ピロー型は、上と底の区別がない（左右の口が同じ作り）。「上」「底」ではなく、「左の口」「右の口」と呼ぶ（2026-11-22 に作った）。口を開けると、外側の正面のフラップが先に起き、そのあとで内側の背面のフラップが起きる。フラップは箱の外側を回って起き、途中でふくらみが平らになって裏返る（口を押して開けるときの、紙の動きに近づけた）。
- 組み立ては、その右に置く。開け閉めと同じく、スライダーの左に「展開図」「箱」が切り替わるボタンを 1 つ付ける。
- どちらの途中でも、柄を選べて、動かせる。
- 出力の工程の箱開け動画は、開け閉めの動きを時間軸にしたもの。

### 裏（内側）への配置

紙の表と裏を、別々の面として持つ。レイヤーの欄は「表」と「裏」に分けて並べる。

- 立体で置く: 下の帯で箱を開けて、見えた内側の面に柄をドラッグする。
- 展開図で置く: 「裏」の表示を出して、同じ操作で置く。
- 置いたあとで移す: 右のプロパティの「紙の面」で、表と裏を入れ替える。場所は同じ（ちょうど裏側）。

持ち方（2026-11-21 に実装）。

- 裏の柄も、場所は表と同じ展開図の座標で持つ。絵は、裏から見て正しく読めるように、左右を逆にして描く。
- プロパティの位置と回転は、裏の柄では「裏」の表示（表を左右に裏返した向き）で見たときの値を出す。定規と数値が合う。
- 柄は、置かれている側の面の上だけを動く。表の柄は箱の外側、裏の柄は内側。面のつながり（折り線と合わせ目）は、表と同じものを使う。
- 裏には、のりしろの斜線を出さない（のりを付けるのは表の面）。
- 型紙の PSD は、表と裏の 2 つ。裏に柄があれば、裏の型紙を「_裏」を付けた名前で一緒に保存する。裏の型紙は、裏から見た向き（2026-11-22）。

### 生成AIと、画像の調整

旧パケノバの仕様を確かめた。陰影の除去、面の端の線の除去、色数を絞る、カラースワップは「素材の画像の調整」の一部で、端末の中で処理する、元の絵を壊さない操作だった。ベクター化は素材ごとの操作で、「AI 生成へ独立のメニューを増やさない」と決めていた。どれも、生成AIの中には入っていなかった。

新パケノバでも分ける。

| まとまり | 入るもの | 置き場 |
|---|---|---|
| 生成AI | 指示を入れて生成、候補の一覧、箱の上での見比べ、「柄として残す」。生成した絵を面へ割り付ける処理と、生成に渡す箱の形の画像（輪郭、奥行き）を作る処理も、この中で行う | 左の道具の帯のボタンで開く、左の欄（4.6） |
| 画像の調整 | 切り抜き、背景を透明にする、陰影の除去、面の端の線の除去、色数を絞る、カラースワップ | 画像の柄を選んだときの、右のプロパティの欄の「調整」。右クリックのメニューにも出す |
| 変換 | ベクター化（元の画像は残し、ベクターの柄を新しく足す）。VectorCraft の画像トレースを部品として使う | 同じ「調整」の並びの最後 |

- 分ける理由: 画像の調整は、生成した絵にも、自分で描いた絵にも使う。生成AIの中に入れると、自分の絵を調整したい人が見つけられない。処理も性質が違う（生成AIは外のサーバーに頼み、結果が毎回変わる。調整は端末の中で、同じ設定なら同じ結果）。
- つなぎ目: 生成した絵は陰影や折り目が入りやすい。「柄として残す」の直後に、「陰影を除く」への近道を 1 行出す。
- PhotoCraft との分担: 上の調整は、箱の形を知っていないとできないもの（面の端の線の除去）と、1 手で済ませたい軽いもの。それ以上の加工は、詳しい編集（PhotoCraft）に任せる。
- 背景を透明にする、陰影をならす（陰影の除去）、色数を絞る、余白を切り落とすは、新しく書いて入れた（2026-11-22、12 章）。面の端の線の除去とカラースワップは、まだ入っていない。旧パケノバの実装（TypeScript）からの移し替えが要る。
- ベクター化は、旧パケノバから移さず、VectorCraft の画像トレースを部品として使う（2026-11-22 に決めた）。VectorCraft は Illustrator の画像トレースにならった作りで、ライセンスもパケノバと同じ。自前で書くより早く、質も高い。上流を上げるたびに、追いかける手間は出る。

## 4.6 素材の扱い（案）

旧パケノバには、案件共通の素材ライブラリ（ロゴ、写真、模様。タグ、検索、版の管理、アーカイブつき）と、ブランドキット（承認の状態と使用規定を持つロゴ。最小サイズや余白を自動で検査）があった。新パケノバでは、まだ何も決めていなかった。次の形を提案する。

### 3 つの置き場

| 置き場 | 中身 | 近いもの |
|---|---|---|
| この案件の素材 | いまの箱に取り込んだ画像やベクター。案件のファイル（`.pknb`）の中に、元のファイルのまま入る | Photoshop の埋め込みのスマートオブジェクト |
| コレクション | 案件をまたいで使い回す素材の集まり。ブランドのロゴ一式、柄のベース、よく使う写真など。パソコンや共有ドライブの「フォルダ」を登録するだけ | Photoshop の CC ライブラリ、Affinity のアセット |
| 付属の見本 | 最初から入っている、権利の問題がない自作のロゴ、模様、飾り | 旧パケノバの標準サンプル |

- コレクションから箱に置くと、その素材は案件の素材に写しが入る。案件のファイルだけで完結し、人に渡しても欠けない。
- 外のファイルとのつながり（リンク）は持たない。素材を新しくしたいときは、手で差し替える。差し替えると、その素材を使っているすべての柄が新しい絵になる（2026-11-22 に決めた。くわしくは [案件の保存の検討](project-file.md) の 5 章）。
- 案件の素材には、箱で使っているかどうかの印と、使っている数を出す。

### 画面での置き場

デザインの工程の左に、道具の帯とは別に、開け閉めできる「素材」の欄を置く。道具の帯の下のボタンで開く。素材を箱へドラッグすると、柄になる。

- 素材をクリックしたら、選ぶだけ。置かない（はじめの実装は、クリックで正面に置いていた。大きく見ようとして押すたびに柄が増える、という指摘で改めた）。
- 選んだ素材は、欄の下に大きく出す。名前、画像の大きさ、置く大きさ、箱で使っている数。「正面に置く」のボタン。
- 絵の大きさは、スライダーで変えられる。欄の幅も変えられる。
- 運んでいる間は、いま放したら置かれる姿を、箱や展開図の上に仮に描いて見せる。置いてから「思っていたのと違う」を防ぐ。
- 立体に置くときの向きは、画面で見て上が上になるようにする（面の辺にそろえて、90 度刻み）。展開図に置くときは、展開図の上が上。
- 道具の帯の「画像」の道具は、やめた。置くのは素材の欄からのドラッグで足りていて、押す意味がなかった。Photoshop にも、画像を置くための道具はない。
- 素材が大量になったときは、この欄ではなく、「素材」の画面で探す（次の節）。

生成AIの候補も、同じ左の欄に出す。「左は選ぶもの、右は選んだものの設定」という役割にそろえるため（型の工程の左が型の一覧、出力の工程の左が出力の種類なのと同じ）。はじめは右のパネルと考えていたが、この形に改めた。

### 素材の画面（管理する場面）

2026-11-21 に決めた。素材には 2 つの場面があり、1 つの欄に詰め込まない。

| 場面 | やること | 置き場 |
|---|---|---|
| 置く | いま使うものを、数個の中から選んで、箱へ運ぶ | デザインの工程の、左の素材の欄 |
| 管理する | 大量の中から探す、見比べる、取り込む、整理する | 「素材」の画面。画面を広く使う |

旧パケノバにも、制作の流れとは別の「リソース用のワークスペース」として、素材ライブラリの画面があった（一覧とタイルの切り替え、検索、絞り込み、並べ替え、複数選択。画像の確認を優先した詳細）。左の欄だけにしたところ、「絵が小さい」「大量だと確認しづらい」という指摘が出た。

- 入口: 上の帯の右側に「素材」を置く。工程（型、デザイン、出力）の並びには混ぜない。流れの一部ではなく、いつでも開く「リソース」のため。左の素材の欄にも「大きく開く」のボタンを置く。
- 並び: 左に置き場の一覧（この案件の素材、コレクションのフォルダ、付属の見本）。中央に、大きなタイルか一覧と、検索、並べ替え。右に、選んだ素材の大きなプレビューと情報（名前、元のファイル名、解像度、更新日、箱で使っている数）。
- 立体は出さない。管理の場面では、画面を素材に使い切る。置いたときの見え方は、デザインの工程で運んでいる間の仮の姿で確かめる。
- 「この案件に取り込む」で、選んだ素材を案件の素材に入れる。デザインへ戻ると、左の欄に入っている。
- 行き来しても、選んでいる柄と、表示の状態は保つ。
- 左の素材の欄は残し、置くための軽い欄にする。出すのは、この案件の素材と、最近使ったもの。
- タグは、フォルダ分けで足りるかどうかを見てから決める。

作る順は、案件の保存、コレクションとこの画面、左の欄を軽くする、の順。この画面の中身は、案件の保存とコレクションが土台になる。2026-11-22 に、この画面とコレクション、左の欄の「最近使ったもの」を作った。

### 道具の帯と素材の欄の並び

左から「道具の帯、素材の欄、箱」と並べる。ほかの並びと比べた（2026-11-21 に各ツールの公式の説明などで確認）。

| 並び | 同じ並びのツール | 良い点 | 弱い点 |
|---|---|---|---|
| ア. 道具、素材、箱（この案） | Adobe Dimension、Substance 3D Painter。Figma も、左端の細い帯の隣にアセットの欄が開く | 道具は画面の左端から動かない。素材の欄を開け閉めしても、道具も右のパネルも位置が変わらない。帯のボタンのすぐ隣に欄が開く | 素材の欄を開いている間、道具と箱が欄の幅だけ離れる |
| イ. 素材、道具、箱 | Premiere Pro（プロジェクトパネルとタイムラインの間に道具） | 道具がいつも箱の隣にある | 素材の欄を開け閉めするたびに、道具の帯が横へ動く。動かさないためには欄を常に開けておくことになり、箱が狭くなる |
| ウ. 道具、箱、右に設定と素材 | Photoshop、Illustrator（CC ライブラリは右のパネルの列） | 森川さん（P1）の手に最もなじんだ並び | 右は設定とレイヤーで埋まっている。タブで重ねると、素材を選ぶ間レイヤーが見えない。列を足すと箱が狭くなる。素材と生成AIの候補を主役にしにくい |

ア を選ぶ理由は 3 つ。立体に絵を置くツール（Dimension、Painter）がこの並びであること。道具の位置が変わらないこと。パケノバでは素材を置くことがデザインの工程の中心で、Photoshop のライブラリのような脇役ではないこと。

弱い点への手当て: 道具はキー 1 つで切り替えられるようにする（9 章）。素材の欄は閉じられ、幅を変えられ、開け閉めの状態を覚える。

ただし、紙の上の比較だけでは決めきれない。実装するときに ア と イ を設定で切り替えられるようにしておき、Windows で触ってから決める。

### 柄のベース

2 種類に分ける。

| 種類 | 内容 | 置き場 |
|---|---|---|
| 模様や地紋 | 面に敷く絵。1 枚の絵、または繰り返しの模様 | コレクション。置くときに「面いっぱい」「繰り返し」を選ぶ |
| デザインのひな形 | 箱 1 つぶんの配置（ロゴの位置、帯、地の色など）のまとまり | 型の工程で、型と一緒に選ぶ。柄はパネルの中での位置で持っているので、寸法を変えても配置が付いてくる |

### ブランドキット

段階を分ける。

- 最初: コレクションの 1 つとして扱う。ロゴのファイルと、ブランドの色の一覧だけ。色は、色を選ぶ小さな窓に出す。
- その後: 使用規定の自動検査（最小サイズ、まわりの余白、縦横比、許可された色）。旧パケノバの `.pds-brand-kit` を読み込めるようにする。

### 旧パケノバから引き継がないもの

版の管理、アーカイブ、案の時点への固定（どれも、レビューと案の履歴のための仕組みだった）。制作者や説明の欄。

## 5. 文字

### 画面の文字の、フォントの優先順

| OS | 優先順 |
|---|---|
| Windows | Yu Gothic UI → Meiryo UI → OS の既定 |
| macOS | ヒラギノ角ゴシック → OS の既定 |
| Linux | Noto Sans CJK JP → OS の既定 |

欧文と数字も、同じ日本語フォントの字形を使う。別の欧文フォントと組み合わせると、数字と mm の並びがそろわず、寸法の欄が読みにくくなるため。

配布する版では、フォントを同梱する選択肢がある。PhotoCraft は、日本語フォントを任意のビルド入力（craft-fonts）から同梱し、なければ OS のフォントを使う。同じ作りにすれば、PhotoCraft と見た目がそろう。

| 選択肢 | 良い点 | 弱い点 |
|---|---|---|
| OS のフォントを使う（いまの作り） | 配布物が小さい。OS になじむ | OS ごとに字幅が違い、欄からはみ出す場所が変わる |
| フォントを同梱する（PhotoCraft と同じ） | どの OS でも同じ見た目。画面の確認が 1 回で済む | 配布物が数 MB 増える。フォントのライセンス表記が要る |

推奨は、開発中は OS のフォント、配布する版は同梱。

### 文字ツールのフォント一覧の並び

文字ツールを作るときの方針。上から、この案件で使っているフォント、最近使ったフォント、すべてのフォント。すべてのフォントは、和文と欧文に分け、それぞれ名前順。名前は、そのフォント自身の字形で見本を出す。

### 文字の大きさ

大きさは 3 段だけにする。数を増やすと、場所ごとにばらつく。

| 役割 | 大きさ | 使う場所 |
|---|---|---|
| 本文 | 13 px | ラベル、ボタン、数値、メニュー |
| 補足 | 12 px | 単位、状態の帯、説明の 1 行 |
| 見出し | 13 px の太字 | パネルの名前 |

- 12 px より小さい文字は使わない。日本語は、欧文より小さい文字が読みにくい。
- 画面全体の拡大率を、設定で 100、125、150% から選べるようにする。OS の表示倍率にも従う。
- 数値は右にそろえ、単位（mm、度）を必ず添える。
- 太さは、標準と太字の 2 つだけ。色で強弱を付けるときは、本文、補足、無効の 3 段。

旧パケノバは本文 14 px だった。従来のクリエイティブツールは 11〜12 px が多い。その間の 13 px にした。

### 画面の言語（2026-11-22）

日本語と英語。ほかの言語を、コードを変えずに足せる形にした。作りは VectorCraft と同じ。

- コードの中では、画面の文字を英語で書き、`t!("…")` で包む（部品 `pakenoba-i18n`）。英語が基準の言葉で、訳がなければ英語のまま出る。
- 訳は、言語ごとの訳の表 `crates/pakenoba-i18n/catalogs/<言語>.tsv` に書く。1 行に「文脈、英語、訳」をタブで区切る（VectorCraft の訳の表と同じ形なので、共通の言葉は流用できる）。値の入る場所は `{name}` や `{}` で、訳の文では順番を変えてよい。
- 言語を足すには、表を 1 つ置いて、`LANGS` に 1 行足す。
- パネルの名前（正面、上のフタ など）は、案件のファイルに書く名前なので日本語のまま持ち、表示するときに文脈 `panel` で訳す（英語の表 `en.tsv` に、英語の名前がある）。
- はじめは OS の言語に合わせる（日本語の OS なら日本語、それ以外は英語）。「編集」→「環境設定」→「言語」で、「システムと同じ」「English」「日本語」を選べ、すぐに切り替わる。選んだ言語は設定に覚える。「言語」の項目は、どの言語でも英語の「Language」を添えて、読めない言語にしても戻れるようにした。
- 型紙の PSD のレイヤーの名前（絵柄、立体の柄、ガイド、紙の裏）は、書き出したときの言語で書く。読み込むときは、どの言語の名前でも見分ける（日本語で書き出した前の型紙も、英語の画面で読める）。
- 自動の試験で、コードの `t!` の文がすべての言語の表にあること、表に使っていない文が残っていないことを確かめる。訳を足し忘れると、どのファイルのどの文かが出る。
- 英語は、ボタンの文字が長くなりやすい。右の欄の幅を、デザインの工程で 280 から 310 px、型と出力の工程で 300 から 320 px に広げた。
- 英字の名前は「PAKENOBA」（方針メモの決定どおり）。
- コマンドラインの使い方の説明と、開発用の文（試験、`expect` の文）は、英語だけ。

## 6. ツールチップ

- アイコンだけのボタンには、必ず付ける。中身は、名前とショートカット（例: 「選択 (V)」）。
- カーソルを置いて約 0.5 秒で出す。一度出たら、隣のボタンへ移ったときはすぐ出す。
- 1 行が基本。説明が要るものだけ、2 行目に 1 文で添える。
- 押せないボタンには、押せない理由を出す（例: 「柄を選ぶと使えます」）。
- ツールチップにしかない情報を作らない。なくても操作できることが前提。
- 文字のあるボタンには付けない。ラベルと同じ内容の繰り返しになるため。

## 7. ポップアップとダイアログ

- 作業を止めるダイアログは、取り返しのつかない操作だけに使う（上書き保存、案件を閉じるときの未保存の確認）。
- 戻せる操作には、確認を出さない。「元に戻す」で戻せるようにする。柄を消すのも、確認なしで消して、戻せる。
- うまくいった知らせは、画面の下の状態の帯に 1 行で出して、数秒で消す。ダイアログにしない。
- 失敗は、起きた場所の近くに、何が起きたかと次にできることを出す（例: 「この PSD は読めませんでした。別名で保存し直してみてください」）。
- 色、フォント、型の選択のような小さな選択は、押したボタンのそばに開く小さな窓にする。外を押すと閉じる。
- ファイルを開く、保存するは、OS のダイアログを使う。
- 右クリックのメニューには、その場で使える操作だけを並べる。同じ操作は、上のメニューにも必ずある。
- 初回の案内は、ツアーにしない。柄が 1 つもないときに、中央に「画像をここにドロップ」のような 1 行を出す。

## 8. 色と見た目

- 既定は暗いテーマ。画面は無彩色のグレーにして、制作物の色の判断を邪魔しない。明るいテーマは後で足す。
- パケノバの色（ティール）は、選択中と、いちばん主なボタンにだけ使う。
- 赤は失敗、橙は注意にだけ使う。型紙の検査の「問題」と「注意」がこれにあたる。
- アイコンは、線だけの単色。大きさは 16 px と 20 px の 2 つ。

## 9. 操作

| 操作 | 割り当て |
|---|---|
| 柄を動かす | 柄をドラッグ |
| 大きさを変える | 選んだ柄の四隅のつまみをドラッグ（展開図でも立体の上でも）。はじめは縦横比を保つ。Shift で比率を外す、Alt で中心を動かさない（Photoshop の今の自由変形と同じ。2026-11-24 に作った。それまでは右の欄の数値だけだった） |
| 回す | 角の少し外側（つまみの外 22 px まで）をドラッグ。Shift で 15 度刻み |
| 縦横比 | 右の欄のプロパティで、幅と高さを 1 行に並べ、間に鎖のボタン（Photoshop と同じ形）。つないでいるあいだ（はじめ）は比率を保つ。外すと別々に変わり、角のつまみも Shift で比率を保つ側に入れ替わる（2026-11-24。それまでは、帯のほかは常に比率を保っていた） |
| 箱を回す | 何もないところをドラッグ。または、Alt を押しながらドラッグ |
| 表示をずらす | スペースを押しながらドラッグ |
| 拡大と縮小 | ホイール。Ctrl+0 で全体を表示 |
| 元に戻す、やり直す | Ctrl+Z、Ctrl+Shift+Z |
| 道具の切り替え | V 選択、T 文字、U 図形、H 手のひら |
| 柄を消す | Delete。確認は出さない（元に戻せる）。いくつも選んでいれば、まとめて消す |
| いくつも選ぶ | Shift を押しながらクリック（足す、外す）。Ctrl+A ですべて。Esc で選ぶのをやめる |
| 詳しい編集 | 柄をダブルクリックか Ctrl+E（画像は外のアプリで開く。文字は右の欄で打つ） |
| その場の操作 | 右クリック。柄（箱、展開図、レイヤーの欄）では、素材を差し替える、この柄だけ差し替える、消す。素材の欄の素材では、素材を差し替える |
