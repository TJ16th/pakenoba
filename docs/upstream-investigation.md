# PhotoCraft / VectorCraft 調査メモ

- 調査日: 2026-11-20
- 方法: リポジトリを取得して、設計文書、Cargo の設定、公開されている型や関数を読んだ。ビルドと実行はしていない。
- 目的: 新パケノバから部品として使える範囲と、編集画面を内蔵できるかを確かめる。

| リポジトリ | 版 | 読んだコミット |
|---|---|---|
| storytold/photocraft | 0.23.1 | `21c551d7` |
| storytold/vectorcraft | 0.24.1 | `aa78136b` |
| storytold/craft-libs | 0.1.0 以降の main | `9eb02be8` |

## 結論

1. 2つのアプリの下に、共有ライブラリ `craft-libs` がある。新パケノバが直接使うべき部品の多くはここにある。
2. 編集機能の本体（エンジン）は UI から切り離されていて、画面なしで動かせる作りになっている。
3. 編集画面をそのまま内蔵する道は、VectorCraft には用意がある。PhotoCraft には見当たらない。
4. 2つの画面を1つのアプリに同時に入れるには、土台のバージョンをそろえる作業が要る。上流を上げるたびに発生する。
5. 上流自身は、PhotoCraft から VectorCraft を「外部アプリとして起動し、保存を検知して取り込む」方式でつないでいる。
6. 日本語 UI は両方にある。Windows の日本語入力は PhotoCraft 側に既知の問題の記載があり、実機確認が必要。

以上から、方針メモの「まず外部呼び出し、その後に内蔵」という段階分けは妥当と判断する。加えて、最初の段階はエンジンすら組み込まず、`craft-libs` の部品だけで始められる見込みがある。

## 1. craft-libs（共有ライブラリ）

2つのアプリは `craft-libs` という別リポジトリに依存している。約 200 個の部品（crate）を持つ Rust のモノレポで、ライセンスは MIT または Apache-2.0。

新パケノバに関係しそうな部品:

| 部品 | 内容 | 新パケノバでの用途 |
|---|---|---|
| `craft-psd` | PSD/PSB の読み書き。未編集のファイルはバイト単位で同じものを書き戻せる。どのアプリにも依存しない | PSD の入出力 |
| `craft-svg` | SVG の読み書きと描画 | SVG 素材の表示と入出力 |
| `craft-pdf` | PDF の読み書き | 実寸の型紙、PDF 互換 AI の読み込み |
| `craft-video` | H.264、ProRes などの動画圧縮（外部ソフト不要） | 箱開け動画の書き出し |
| `craft-media` | MP4、MOV などの入れ物の読み書き | 同上 |
| `craft-mesh` | glTF、OBJ、STL などの 3D モデルの読み込み | 箱の中身（商品）の 3D モデル |
| `craft-ui` | ボタン、タブ、分割、ドッキングなどの画面部品。9 つの制作系アプリで共用 | 見た目と操作感をそろえる |
| `craft-i18n` | 翻訳カタログの仕組み | 日本語と英語の UI |
| `craft-keymap`、`craft-window`、`craft-settings` | ショートカット、ウィンドウ枠、設定保存 | 同名の用途 |

確認できたこと:

- `craft-psd` には、PSD に保存されている統合画像を取り出す関数がある（`composite_rgba8`）。レイヤーを自前で合成しなくても、箱に貼る絵は得られる。
- `craft-svg` には描画機能がある（`tree-render`）。
- バージョン方針が文書化されている。リリースはタグで固定し、0.x の間も同じ系列内は互換を保つとしている。
- 依存はすべて git 指定で、crates.io には未公開。

注意点:

- 説明文は「Craft Apps が使うライブラリ」としていて、外部のアプリが使うことはライセンス上は自由だが、想定された使い方ではない。
- 正式リリース `v0.1.0` に含まれるのは 5 部品だけ（`craft-ui` など）。PSD や動画の部品は main の特定コミットを指定して使うことになる。2つのアプリ自身もそうしている。
- 利用する部品はすべて同じコミットにそろえる必要がある。混ぜると同じ型が二重になり、互いに渡せなくなると明記されている。

## 2. エンジンと UI の分離

両方とも、層の上下関係をビルド時に検査している。UI の道具（egui、eframe、winit）に依存してよいのは最上位の2層だけ。

- PhotoCraft: 約 54 万行、ライブラリ 25 個。すべての操作は約 700 個のコマンドとして登録され、UI、コマンドライン、制御チャネル、MCP が同じコマンドを呼ぶ。
- VectorCraft: 約 35 万行、ライブラリ 23 個。コマンドは約 710 個。構成は同じ考え方。
- どちらにも画面なしのコマンドライン版がある（`photocraft-cli`、`vectorcraft-cli`）。ファイルを開いてコマンドを実行し、書き出せる。

注意点:

- PhotoCraft の設計文書には初期の計画が残っていて、実際のコードと違う箇所がある。計画にある `viewport`、`tools`、`platform`、`psd` という部品は、現在のリポジトリには存在しない（`psd` は `craft-libs` に移動済み）。文書の関数名をそのまま当てにはできない。
- アプリ内部の部品に、互換性の約束は書かれていない。上げるたびに手直しが出る前提で考える。

## 3. 編集画面を内蔵できるか

### VectorCraft: 用意がある

- 画面全体を表す型（`VectorcraftApp`）が公開されていて、`new`、`logic`、`ui` を外から呼べる。`ui` は描く場所を引数で受け取る。
- 開発文書に「embedder（組み込む側）」向けの節がある。エンジンだけを使う場合と、パネルも含めて使う場合のそれぞれについて、フォントの同梱を切る設定が説明されている。

### PhotoCraft: 見当たらない

- 画面全体を表す型（`PhotocraftApp`）はあるが、アプリの枠組み（eframe）に結びついた形で実装されている。
- 組み込む側に向けた説明は見つからなかった。

### 共通の制約

- どちらの `ui` も「ウィンドウ全体を配置する」前提で書かれている。メニューバーやパネルを含む画面一式が出るので、新パケノバの画面の一部として収めるには調整が要る。
- 2つのアプリは、改変版の egui（`storytold/egui`）を使っている。しかも指定しているコミットが互いに違う。`craft-libs` のコミットも違う。
- 1つのアプリに入れられる egui は1つだけなので、両方の画面を同時に内蔵するには、どちらかを動かしてそろえる必要がある。そろえた状態でビルドが通るかは未確認。

## 4. 上流自身の連携方式

PhotoCraft には、埋め込まれたベクター（SVG、PDF 互換 AI、PDF、EPS）を VectorCraft で編集する機能がある。方式は次のとおり。

- 作業用のコピーを非公開の場所に作り、VectorCraft（または指定した別のアプリ。Illustrator も選べる）を起動して開く。
- 保存を検知して、元のスマートオブジェクトを更新する。保存1回が取り消し1回分になる。
- プレビューの生成には `vectorcraft-cli` を画面なしで裏で動かす。
- 対応する実装は `apps/photocraft/src/external_svg.rs` などにあり、参考にできる。

つまり、同じ作者の2つのアプリの間でも、内蔵ではなく外部起動でつないでいる。新パケノバが同じ方式から始めるのは、上流の実績に沿った選択になる。

なお同じ文書に、AI/PDF/EPS は「形式は保つが、Illustrator と同等の無劣化編集を保証するものではない」とある。Windows と macOS での実機確認は未実施とも書かれている。

## 5. 外から操作する仕組み

- 制御チャネル: 自分の PC 内だけで待ち受ける通信口に、1行1件の JSON を送る方式。実際のマウスやキー入力の再現、画面の取得ができる。
- PhotoCraft は接続にトークンが必要。VectorCraft は認証なしと明記されている（使うときだけ有効にする前提）。
- 読み書きできるフォルダを起動時に限定できる。
- MCP サーバーは各コマンドライン版から起動する。

## 6. 日本語

| | PhotoCraft | VectorCraft |
|---|---|---|
| 日本語 UI | あり（翻訳率 93.5%） | あり（翻訳率 99.6%） |
| 日本語フォント | 別リポジトリ `craft-fonts` をビルド時に指定すると同梱 | 同じ |
| 日本語入力 | 「Windows の日本語入力」が不足項目に挙がっている（#590） | 「対応済み」と記載 |

#590 が現在も未解決かどうかは、今回は確認できなかった。新パケノバでも文字入力は必須なので、Windows 実機で早めに試す。

## 7. 新パケノバへの当てはめ

| 段階 | 内容 | 上流への依存 |
|---|---|---|
| 1 | `craft-libs` の部品で、PSD と SVG の表示、ファイル入出力、動画書き出し、画面部品をまかなう。編集は外部アプリを起動して行う | `craft-libs` の1コミット |
| 2 | エンジンを組み込み、レイヤー単位の表示や、描いた瞬間の反映を行う | 上に加えて、各アプリのエンジン |
| 3 | 編集画面を内蔵する。VectorCraft から始めるのが現実的 | 上に加えて、各アプリの UI |

段階が進むほど一体感は増すが、上流を上げるときの手間も増える。段階1だけでも「型紙、立体上の配置、出力」という新パケノバ固有の価値は成立する。

## 9. 次の一手（案）

小さな試作を1つ作り、未確認の項目をまとめて確かめる。

1. egui と wgpu のウィンドウに、厚みのない箱を1つ表示する。
2. `craft-psd` で PSD を読み、箱の面に貼る。
