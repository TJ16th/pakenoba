# 新パケノバ 方針メモ

- 作成日: 2026-11-20
- 状態: 構想段階（コードはまだない）
- 旧版: `packageDesign20260711`（TypeScript + Vite + Three.js + Electron、非公開）

この文書は、2026-11-20 の会話で出た方針をまとめたものです。「決定」は本人が明言したこと、「提案」は会話の中で出て大きな異論がなかった案で、まだ確定ではありません。

## 1. 何を作るか

パッケージデザイン専用の制作ソフト。箱の形（型紙）を決め、立体の上で直感的に柄を置き、見せるための画像や動画を書き出すところまでを1本で行う。

## 2. 決定事項

### 配布と位置づけ

- 完全無料で、GitHub で公開する。有料配布はやめる。理由は、小遣いを稼ぐより広く使ってもらうほうがよいと考えを変えたため。
- 正式名称は旧版と同じ「パケノバ」。ロゴとアイコンも旧プロジェクトのものを使う。
- コードのライセンスは「MIT または Apache-2.0」（利用者がどちらかを選べる形）。上流の PhotoCraft、VectorCraft、craft-libs と同じ。
- パケノバの名称とロゴは、コードのライセンスの対象外にして、商標として守る。コードの改造や再配布は自由だが、パケノバの名前とロゴを付けて配ったり売ったりはできない、という線引き。販売を禁じる条項は付けない（付けるとオープンソースと呼べなくなり、広がりにくくなるため）。
- 旧版の基本コンセプトは踏襲する。
- レビュー機能（レビュー回、コメント、評価、共有フォルダ協業など）は入れない。純粋な制作ソフトにする。
- ただし、見せるための出力フォーマットは残す（5章）。

### 箱の表現

- 厚みのある紙を折って箱にする表現に対応する。ベロ、内側への折り返し、型紙の選択を含む。
- 旧版の「直方体の展開図を折るだけ」も引き続き対応する。
- 手提げ型のような曲面を含む箱も、最初から扱える設計にする。
- 型紙の精度はデザイン確認用でよい。目安は「デザイナーが厚紙に印刷して、自分で折って組み立てられる」程度。製造用の型紙は箱の専門業者が作る前提。
- 三角柱や五角柱などの変わった箱は、将来対応できるとよい。
- 箱の種類は大きく2つに分ける（3章）。

### 編集機能

- 画像編集とベクター編集は自作しない。PhotoCraft と VectorCraft のコードを活用する。
- 生成AIでデザインを支援する機能は踏襲する。
- デザイナーはこのソフトで完結できるのが基本。ただし PSD や AI ファイルとの行き来にも対応する。直接出せれば最良、SVG などの中間フォーマット経由でもよい。

### 動作環境と技術

- PC 上で軽快に動くこと。
- Adobe のツールや PhotoCraft と並べて違和感のない操作感であること。
- 可能なら macOS でも動くこと。
- 実装言語にこだわりはない。Rust への抵抗もない。

### 画面

- 独自色の強かった旧版の UI から、既存のクリエイティブツールに寄せた UI にする。
- 「型紙を決める → 配置する → 書き出す」という大きな流れは分かりやすく保つ。
- 素材を詳しく編集するときだけ、PhotoCraft や VectorCraft のフル機能に切り替わる形にする。

### 進め方

- バージョン管理しながら進める。作業フォルダは `pakenova2`。

## 3. 箱の2つのタイプ

| | 展開図タイプ | 立体タイプ |
|---|---|---|
| 正本 | 型紙（パネルと折り線のつながり） | 組み上がった形そのもの |
| 柄を置く場所 | 紙の表と裏 | 立体の各面 |
| 厚み | 紙の厚みとして折りに反映 | 形に最初から含まれる |
| 開ける動き | 折りを開く＋パーツを動かす | パーツを動かすだけ |
| 固有の出力 | 実寸の型紙 | 面ごとの実寸の絵柄 |
| 例 | 差し込み箱、段ボール箱、手提げ型 | 貼り箱の身とフタ、中皿、中身 |

旧版の「直方体に UV で貼る」は立体タイプにあたる。立体上で柄を置く操作、面またぎ、加工の指定、出力は、どちらのタイプでも同じ仕組みを使う。

## 4. 設計の提案（未確定）

「型紙の持ち方」のうち、平らなパネルを折る部分は、試作 S02 で成り立つことを確かめた（差し込み箱と、三角柱から八角柱まで）。曲面を含む型と、柄をパネル基準で持つ部分は、まだ試していない。

### 型紙の持ち方

- 型紙を「平らなパネルの集まり」と決め打ちにしない。「展開図上の点が、開き具合に応じて立体のどこに来るかを返すもの」として定義する。平らなパネルの汎用組み立ても、曲面の型ごとの専用計算も、同じ枠に収まる。
- パネルは任意の多角形、折り角は任意の角度にする。角柱や台形の箱にそのまま広げられる。
- 柄はパネル基準の位置で持つ。寸法や厚みを変えても追従できる。
- 厚みは「折るたびに紙の厚さぶんずらす」程度の単純なルールにする。

### 面をまたぐ配置

- 折り線でつながった面どうしは、展開図上でも地続きなので自然に連続する。
- 立体では隣だが展開図では離れている面（のりしろの合わせ目など）は、型紙ごとの「組み立て後にどの辺とどの辺が接するか」の情報から自動で分割して描く。
- 3面が集まる角をまたぐ配置は、平面に開けないため制約が残る。

### 土台に最初から入れるもの

- 紙の表と裏の2面（内側の印刷）
- 複数パーツの組み合わせ（身とフタ、外箱＋中皿＋取説、スリーブと引き出し、帯や掛け紙）
- 開ける手順（パーツごとの動きを段階として並べる。箱開け動画の台本になる）
- 中身（商品、個包装、トレイなど。印刷はしないが見え方を決める）
- 窓と抜き（フィルムのある窓、ない窓、持ち手の穴、吊り下げ穴）
- 紙の地色と加工（箔押し、エンボス、ニスなどを柄ごとに指定）

### 最初の版に入れる型（案）

1. 厚みとベロのある直方体（展開図タイプ、汎用組み立て）
2. 手提げ型（展開図タイプ、曲面の専用計算）
3. 次の段階で、身とフタ、フタ一体の段ボール箱

### 画面構成

- ワークスペースは「型」「デザイン」「出力」の3つ。左から順に進めば完成し、いつでも行き来できる。
- 箱の立体表示は常に中央に置く。ワークスペースで変わるのは周りの道具だけ。
- パネルの自由な並べ替えは最初は作らない。
- デザインのワークスペースは2層にする。普段は配置中心の少数のツールだけを見せ、素材を詳しく編集するときにフル機能へ切り替える。
- 生成AIは独立したワークスペースにせず、デザインの中のパネルにする。

### 素材の編集と外部アプリ

- 素材はプロジェクトフォルダ内の独立したファイル（PSD、SVG など）として持つ。
- 描画とファイルの読み書きは内部に持つ。
- フル編集は、まず外部アプリの呼び出しから始める（保存を検知して箱に反映）。Photoshop、Illustrator、Affinity も同じ仕組みで使える。
- その後、内蔵のフル編集に進む。

根拠と実現性は `upstream-investigation.md` を参照。

## 5. 出力

ワンボタンで出力プリセットを選んで書き出す。どれも「シーン、カメラ、箱の開き具合を決めてレンダリングする」同じ仕組みで作る。

- 16:9 の画像（スライド用）
- 箱開け動画
- 店の棚に並べた絵
- 実寸の型紙（切り線、折り線、絵柄入り。A4 や A3 に分割印刷できる形）

## 6. 外部ファイルとの行き来

- PSD: 直接の読み書きを目指す。
- AI: 当面は PDF または SVG 経由。「PDF 互換」付きで保存した .ai は読める見込み。
- 行き来の単位は2種類。展開図まるごと（絵柄はレイヤー、切り線や折り線はロックしたガイドレイヤー）と、素材1つだけ。
- 割り切り: 合わせ目をまたぐ柄は、展開図まるごとの往復では「展開図に貼られた絵」として戻ってくる。

## 7. 旧版から引き継ぐもの

- 座標と UV の規約（ADR-0001、ADR-0007）
- ComfyUI 連携の考え方と信頼境界（ADR-0003）
- AI 生成画像の UV 投影、陰影と折り目の除去、ベクター化、カラースワップ
- 表示プリセットと成果物フォーマットの考え方
- 「操作と3D確認を同じ画面に置く」という方針
- 日本語と英語の UI、ライトとダークのテーマ
- 「製造用データではない」という注意書き

## 8. 引き継がないもの

- レビュー回、コメント、評価、Decision
- 共有フォルダによる協業、スナップショット共有
- デザイン案の Revision 管理、品質目標
- Codex 運用のための台帳や各種監査の仕組み

## 9. 後から足すもの

- シリーズ展開（サイズ違い、味違いの色替え）
- 表示の目安（バーコードや成分表示の場所、のりしろの印刷不可エリア）
- 棚のバリエーション（平置き、積み重ね、フック吊り）
- 紙袋や包装紙
- 自由に描いた曲線入りの型紙を自動で折る機能は対象外（紙の物理シミュレーションが必要になるため）

## 10. 未決事項

- 英字の表記と、公開リポジトリの名前。旧ロゴは「PAKENOBA」、今の作業フォルダは `pakenova2`。ロゴに合わせるなら `pakenoba`。
- 公開リポジトリの場所と、公開のタイミング。
- 商標を登録するかどうか。登録しない場合は、リポジトリに「名称とロゴは対象外」と明記するだけの形になる。
- 動画書き出しに使う H.264 の特許の扱い。公開前に確認する。問題があれば別の動画形式に切り替える。
- 生成AIの接続先。旧版はローカルの ComfyUI のみ。
- 最初の版の範囲の確定（4章の案でよいか）。
